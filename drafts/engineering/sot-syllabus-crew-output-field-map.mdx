## Known Issues

### LLM Output Shape Variations

The LLM produces inconsistent shapes for several fields across different syllabi:

- `grade_strategy.gotchas` — sometimes `string[]`, sometimes `Array<{ warning, impact, how_to_avoid }>`
- `grade_strategy.strategic_priorities` — sometimes uses `component` as the name field, sometimes `priority`
- `grade_strategy.grade_scenarios` vs `grade_strategy.scenarios` — key name varies
- `hidden_insights` — sometimes nested object, sometimes sub-fields hoisted to top level, sometimes null

<Warning>
All consumers must handle both shapes. The webviewer `extractIntelligenceFields()` handles these variations. The admin `SyllabusVisualization.tsx` renders raw JSON for most fields so is unaffected.
</Warning>

### Data Preservation Architecture

The crew uses lightweight JSON structure validation (checking `course_code`/`course_title` exist) instead of Pydantic models. Pydantic was removed because `extra='allow'` only applied at the top-level model, not nested models, causing data loss.

The normalizer preserves rich data structures:
- **Policies**: 25-item rich list with category, policy_text, criticality, consequences, etc.
- **Assignments**: All extra keys per item preserved (isFinal, rubric, canvas_id, etc.)
- **Grading**: All extra keys preserved

### Persistently Null Fields

- `cost` — not populated by any task (legacy field)
- `confidence_score` — not populated by any task
- `hidden_insights` — sometimes null (varies by syllabus)

### iOS Model Gaps

`DashboardService.swift` `HiddenInsights` struct is missing:
- `professorStyle: ProfessorStyle?`
- `collaborationPotential: String?`
- `wellnessFactors: [String]?`

### High-Impact Integration Opportunities

**Current utilization**: ~35% of crew output fields are actively consumed by the engine.

High-impact targets for engine integration:
1. `red_flags` → StudentWatcher alerts when approaching flagged scenarios
2. `hidden_workload` → Inflate time estimates in day plan generation  
3. `professor_style` → Personalize study block recommendations
4. `workload_recommendations` → Include in Sunday preview email
5. `recurring_events` + `special_dates` → Generate additional time_blocks
