# Course Term/Date JSON Path Audit

This audit reveals critical inconsistencies in how term IDs and semester dates are stored and retrieved across the codebase, leading to data synchronization issues.

## Critical Issue: Triple Storage Not Synced

<Warning>
Term health fixing operations have three storage gaps that cause wrong semester dates and time block generation issues.
</Warning>

When running term fixes (fix-null-assignments, fix-orphaned-enrollments), the code updates:
- ✅ `context_dependencies.term_id`
- ✅ `context_dependencies.term_year` 
- ❌ **GAP 1**: Does NOT update `context_dependencies.metadata.term`
- ❌ **GAP 2**: Does NOT update `contexts.metadata.semesterDates` (course context)
- ❌ **GAP 3**: Does NOT update `contexts.metadata.startDate/endDate` (course context)

This causes:
1. "current" to persist in enrollment `metadata.term`
2. **Wrong semester dates** (e.g., Fall dates when term is Spring)
3. Time blocks generated with incorrect dates

## The Data Inconsistency Problem

1. **Original course creation** (via schedule import):
   - Saves `metadata.semesterDates = { start: '2026-08-26', end: '2026-12-17' }` (Fall dates)

2. **Admin edits course term** (via Course Details UI):
   - Saves `metadata.term = 'spring_2026'`
   - Saves `context_dependencies.term_id = 'spring_2026'`
   - **Does NOT update `metadata.semesterDates`**
   - **Does NOT update `metadata.startDate/endDate`**

3. **Time block refresh runs**:
   - Reads old Fall dates from `metadata.semesterDates` which take precedence
   - Time blocks use Fall dates even though term was changed to Spring

## CourseFactory.getForStudent() Gap

The main method for getting student courses has a critical issue:

```sql
SELECT
  c.metadata,        -- Only gets course context metadata
  -- other fields...
FROM context_dependencies cd
JOIN contexts c ON c.id = cd.child_context_id  
WHERE cd.term_id = $2  -- Filters by cd.term_id but doesn't SELECT it
```

**Problem**: The query filters by `cd.term_id` but doesn't return it, so the canonical term ID never reaches the frontend.

## Recommended Canonical Paths

<Tip>
Standardize on these paths and migrate everything to use them consistently:
</Tip>

**Course Context Metadata:**
```typescript
metadata: {
  termId: 'spring_2026',           // Normalized format
  termYear: 2026,
  termName: 'Spring 2026',         // Human-readable
  startDate: '2026-01-07',         // Flat keys (not nested)
  endDate: '2026-04-30',
  // DEPRECATED - keep for backwards compatibility:
  term: 'spring_2026',             // Legacy
  semesterDates: { start, end },   // Legacy nested
}
```

**Context Dependencies:**
```typescript
context_dependencies: {
  term_id: 'spring_2026',          // Normalized format  
  term_year: 2026,
}
```
