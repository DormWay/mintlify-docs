# Onboarding Canon

Agent-facing source of truth for the first-run student experience. This doc captures known principles, not a speculative redesign.

## Purpose of Onboarding

Get a new student to first value as fast as possible with no confusion about what DormWay does, what it doesn't do, or what to do next.

## What First Value Means

A student has received first value when they can see their upcoming deadlines and assignments in one place. The canonical first actions (per [GTM Playbook - Spring 2026 (Current)](/docs/product/go-to-market/gtm-playbook-spring-2026-current)) are:

- Syllabus upload
- Schedule import
- Canvas connect

Any one of these counts. The onboarding flow should make at least one of them obvious and reachable.

## Primary Action Principle

Every major surface should have one clear primary action. Onboarding should not present ambiguous branching where students don't know which option to pick first.

## Trust and Copy Constraints

- Do not overclaim what DormWay does (no grade guarantees, no homework automation, no essay writing)
- "We use AI for dates, not essays" — this trust boundary should be visible
- Explain what DormWay reads and what it doesn't
- If students might worry about data, money, or security, address it proactively
- Copy must pass the Riley Test (see [DormWay Framing Guardrails (Current)](/docs/product/brand/dormway-framing-guardrails-current))

## What Should Never Happen in Onboarding

- Student reaches a dead end with no guidance
- Student sees an empty or broken state without explanation
- Student is confused about what DormWay is or what it does
- Student is asked for more information than needed to get first value
- Student sees corporate, jargon-heavy, or AI-hype language
- Onboarding weight increases without clear evidence it improves activation

## Current Priorities (as of March 2026)

*Sourced from [Class of 2030 Workback Plan - March to August 2026 (Draft)](/docs/product/go-to-market/class-of-2030-workback-plan-march-to-august-2026-draft) (status: draft). These reflect active founder intent but may shift. Verify with Riley before treating as committed scope.*

- Reduce onboarding weight
- Reduce ambiguous branching
- Clarify what DormWay reads vs. doesn't
- Improve the "Today" surface so it feels finite, clear, and useful
- Define and ship first-run help/tutorial
- Tighten homepage and onboarding around one primary action

Before changing onboarding:

3. **Copy guardrails:** [DormWay Framing Guardrails (Current)](/docs/product/brand/dormway-framing-guardrails-current) and [GTM Copy Bank - Spring 2026](/docs/product/go-to-market/gtm-copy-bank-spring-2026)
