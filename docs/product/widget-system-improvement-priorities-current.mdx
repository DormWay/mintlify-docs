# Widget System Improvement Priorities

Concrete improvement priorities for DormWay's widget system across web and iOS. Grounded in the current implementation (verified 2026-03-18) and governed by [Today Screen Product Principles (Current)](/docs/product/today-screen-product-principles-current).

This doc answers: "Given the widget system we have, what should we fix, refine, and build next to make it work for every type of student?"

---

## Current State Summary

The LockedIn web Today page is a real customizable widget workspace with 6 canonical widgets: Today (status), Schedule, Tasks, Courses, HeadsUp (Cue), and Notes. It supports drag/drop, resize, hide/restore, add widgets, persistent layout, save/cancel, and auto-organize ("Tidy Up"). Widgets reshape based on available space.

The architecture is strong. The main gaps are: discoverability of customization, incomplete governance on HeadsUp, unfinished inspector system, inconsistent widget behavior across sizes, and missing freshness signals.

For full current-state documentation, see [LockedIn Web Today Page - Current Functionality (Current)](/docs/engineering/technical/lockedin/lockedin-web-today-page-current-functionality-current).

## Top 5 Priorities (Ordered)

### 1. HeadsUp Governance (Phase 2 from Student Life Surfaces Spec)

**Status:** Not started. Most impactful trust improvement.

**What:** Enforce hard caps, require "why shown" on every card, implement dismiss/snooze with undo, lock beta categories.

**Why:** Without governance, HeadsUp becomes noise students learn to ignore. That kills the one surface designed to tell them what actually needs attention. Directly affects whether students trust DormWay's urgency signals.

**Spec reference:** [Student Life Surfaces - Widgets and HeadsUp Spec (Draft)](/docs/product/features/dashboard/student-life-surfaces-widgets-and-headsup-spec-draft), Phase 2 (lines 511-531). Rules already defined:
- Glance: 1-2 cards max
- Expanded: max 10, per-category caps (academic 5, schedule 3, system 2, campus 1)
- Every card: title, "why shown" (one line), primary CTA, dismiss/snooze with undo
- Interrupt rules: only system health and schedule disruptions can interrupt; academic urgency highlights only when due < 6 hours or overdue

**Concrete deliverables:**
- [ ] Enforce card caps in HeadsUp widget rendering
- [ ] Add "why shown" line to every HeadsUp card
- [ ] Ensure dismiss/snooze with visible undo on every dismissable card
- [ ] Lock beta categories (academic urgency, schedule disruptions, system health, campus only if impacts today)

### 2. Customization Discoverability

**Status:** Identified as the #1 UX gap. See [LockedIn Web Today - Customization & Discoverability Memo (Current)](/docs/product/lockedin-web-today-customization-discoverability-memo-current).

**What:** Make edit mode, resize, and customization obvious from the default screen.

**Why:** The widget system is more capable than students realize. If they never discover customization, they experience DormWay as a static dashboard — which undercuts the "every student is different" premise.

**Concrete deliverables:**
- [ ] Make "Edit layout" / "Customize Today" more prominent and clearly tied to personalization
- [ ] Redesign resize handles from small blue dots to unmistakable grab affordances (larger corners + visible edge handles)
- [ ] Demote long-press from primary entry to power-user shortcut only
- [ ] Consider first-visit guided moment showing that Today is customizable (not a full tutorial — one clear signal)
- [ ] Ensure the page reads as "customizable workspace" not "static dashboard" on first view

### 3. Widget Size Contracts

**Status:** Partially implemented. Widgets adapt by size but not deliberately enough. Weak states exist.

**What:** Define explicit content behavior for each widget at each size class: compact (1x1/1x2), medium (2x2), large (2x3/3x3+), and wide vs. tall variants.

**Why:** Students who resize widgets can create states where a widget technically fits but shows nothing useful. Every widget size should be intentional — showing the right amount of information for the space, not just cramming or stretching.

**Size contract framework (from Student Life Surfaces Spec):**
- **1x1/1x2:** 2-3 items max. Focus on next actionable item. Minimum viable glance.
- **2x2:** 4-6 items with one key metadata line each. Default useful state.
- **2x3/3x3+:** Expanded list, quick actions row, insights. Full capability.

**Per-widget contracts to define:**

| Widget | Compact (1x1/1x2) | Medium (2x2) | Large (2x3+) | Notes |
|--------|-------------------|--------------|--------------|-------|
| Today (status) | Time + next event + urgency count | + weather + ambient context | + stat pills + expanded status | Urgency must be visible at all sizes |
| Schedule | Next class + time | Day timeline (vertical) | Full timeline + weather markers + walking time | Can become horizontal ribbon when wide |
| Tasks | Count + next urgent item | Urgency filters + 4-6 items | Full list + create task + detail actions | Course filter chips at large size |
| Courses | 2-3 courses with next due | Full course list + due counts | + risk badges + next class cues | Risk badge is key differentiator |
| HeadsUp | Top 1 card | Top 2 cards + dismiss | Scrollable feed with caps | "Why shown" at all sizes |
| Notes | "Tap to open notes" placeholder | Editor + recent notes | Full editor + recent notes rail + preview/edit | Minimum useful: 2x2 |

**Concrete deliverables:**
- [ ] Document and implement size-specific rendering for all 6 widgets
- [ ] Define minimum useful size per widget (below which it shows a "tap to expand" placeholder)
- [ ] QA all widgets at 1x1, 1x2, 2x2, 2x3, 3x3 sizes

### 4. Inspector System Completion

**Status:** Phase 1 in-progress for Courses. Not started for Tasks, Schedule, HeadsUp.

**What:** Extend the inspector panel (right-side overlay on web, bottom sheet on mobile) to all widgets so students can inspect and act on any item without leaving the dashboard.

**Why:** The progressive disclosure contract says 70%+ of detail opens should happen via panel, not full-page navigation. This makes Today a true workspace — students can drill into a task, check assignment requirements, and navigate back without losing their place.

**Spec reference:** [Student Life Surfaces - Widgets and HeadsUp Spec (Draft)](/docs/product/features/dashboard/student-life-surfaces-widgets-and-headsup-spec-draft), Phase 4 (lines 552-571).

**Concrete deliverables:**
- [ ] Complete Courses inspector QA (Phase 1 sub-checklist in spec)
- [ ] Extend inspector to Tasks widget (task detail, mark complete, priority, course context)
- [ ] Extend inspector to Schedule widget (event detail, edit/delete for editable events)
- [ ] Extend inspector to HeadsUp widget (card detail, actions)
- [ ] Extend selection highlighting to all widgets (currently only Courses)
- [ ] Mobile: inspector as bottom sheet, pinned list (no dock)

### 5. Freshness and Trust Signals (Phase 3)

**Status:** Not started. Important for trust.

**What:** Show when data is current vs. stale. Surface system health issues.

**Why:** If a student sees a deadline that was actually moved yesterday, and DormWay showed stale data without warning, that's a trust-destroying event. Students need to know what they can rely on.

**Spec reference:** [Student Life Surfaces - Widgets and HeadsUp Spec (Draft)](/docs/product/features/dashboard/student-life-surfaces-widgets-and-headsup-spec-draft), Phase 3 (lines 532-551).

**Freshness thresholds:**
- Schedule / next event: < 5 minutes
- Assignments / due dates: < 15 minutes
- System health: < 2 minutes

**Concrete deliverables:**
- [ ] Add freshness metadata to widget payloads (lastSyncedAt, isStale, staleReason)
- [ ] Show subtle stale indicators in Schedule/Tasks/Courses/Today when thresholds exceeded
- [ ] System health HeadsUp card with reconnect/refresh CTA when data is stale
- [ ] Calm copy: "Data may be out of date" + "Refresh" CTA

## Per-Widget Refinements (Beyond Top 5)

### Schedule Widget
- Surface walking time between consecutive events (data exists per SoT - Home & Widgets)
- Consider week view when given enough space (2x4+) — especially for iPad/Mac planning sessions
- Distinguish load-adaptive density: 6-class day should feel tighter than 2-class day

### Tasks Widget
- Add per-course filter chips so students can focus on one class
- Make completion feel good (brief animation, count updates immediately)
- Sharpen "submitted vs. pending" visual distinction
- Ensure small-state shows count + next urgent only

### HeadsUp Widget
- Implement "why shown" on every card
- Enforce interrupt rules (only system health and schedule disruptions can interrupt)
- Consider time-decay: cards that have been visible for 24+ hours without action should dim or auto-snooze

### Courses Widget
- Add risk badge (due count + risk signal per course)
- Ensure compact state shows only the 2-3 highest-priority courses
- Complete course detail enrichment: instructor, meeting time, syllabus, office hours

### Notes Widget
- Auto-link to current class context when student is in class
- Define minimum useful size (2x2) — show placeholder below that
- Consider "quick note" mode at small sizes (just a text input that saves to recent)

### Today (Status) Widget
- Inject urgency alongside temporal state (same as iOS GPS Hero fix)
- Converge conceptually with the iOS GPS Hero — same data model, same priority logic
- Stat pills approach: "Free until 2:30 · 3 due today"

## Future Consideration: Preset Layouts

Not current scope, but worth noting: the "Tidy Up" feature already has opinionated organize logic. This could evolve into 2-3 preset layouts students choose on first load:

- **Schedule-first:** Big schedule, compact tasks, small courses
- **Tasks-first:** Big tasks, compact schedule, prominent HeadsUp
- **Balanced:** Current default

Not a configuration burden — a 3-second choice. Aligns with Principle 8: "The default must be great. Customization is available, never required."

---

## What Not To Do

- Do not add new widgets before the existing 6 are polished across all sizes
- Do not build more customization features before discoverability is fixed
- Do not ship HeadsUp at scale without governance caps
- Do not show stale data without freshness indicators
- Do not conflate default layout criticism with widget architecture criticism — they are separate questions
