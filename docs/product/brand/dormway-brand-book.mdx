## 3) Audience & Personas

**Primary:** Overwhelmed Freshman (wants clarity and relief).
**Secondary:** Ambitious Upperclassman (wants precision and advantage).
**Tertiary:** Social Connector (wants balance across academics and campus life).

**General rule:** Speak to anxious, time-pressed students who want relief without condescension.

## 4) Voice & Tone (Umbrella Rules)

**Voice:** Smart, relaxed, human. Friendly first, credible second, never corporate.

**Golden Rule:** Talk like an upperclassman helping a freshman.

**Always:**
- Problem-first, not feature-first.
- Specific over generic (Canvas, 40-page syllabus, 11pm panic).
- Honest about limitations.
- Empathy over authority.
- Sentence case, natural capitalization.

**Never (General):**
- Corporate jargon (synergize, optimize, revolutionize).
- AI hype or “AI-powered” lead language.
- Guilt loops or shame.
- Trend slang that will age fast.

**Allowed Trust Line (Public):**
- “We use AI for dates, not essays.” (Use only as a trust boundary, not as a headline.)

**Reference SoT:** `Product/Brand/DormWay-Brand-Voice-and-Positioning-Master-Guide.md`

## 9) Workstation & Modular Density (Desk Mode)

DormWay is moving from a utility into a **Student OS**. The UI must scale from glanceable widgets to full workbench tools without losing clarity. This is the “Academic Workbench” layer.

### 9.1 Glance Density (Today)
- **Goal:** 2-second comprehension. Minimal text, high-level counts, one primary action.
- **Rules:**
  - Show totals and next action above the fold.
  - Default state is calm: no heavy grids, no long lists.
  - Use concise labels + counts; avoid paragraphs.
  - Expand details only on intent (tap, hover, open).

### 9.2 Focus Density (Library / Notebooks)
- **Goal:** Maximum screen utility without chaos.
- **Rules:**
  - Multi-pane alignment (left nav, center work, right inspector).
  - Dense lists are allowed, but columns must align across panes.
  - Keep metadata visually lighter than primary text.
  - Avoid full-bleed gradients; preserve scanability.

### 9.3 `useWorkbenchSize` Standard (Unfold Rules)
Define a shared layout hook that governs when a widget “unfolds” into a workstation toolset.

**Suggested breakpoints:**
- `compact` (< 720px): widgets only, single column, no inspector.
- `regular` (720–1100px): split layout, 70/30, optional inspector.
- `expanded` (>= 1100px): full workbench (nav + center + inspector).

**Unfold trigger:** When a user opens a detail panel or long-form tool, switch to the highest supported `useWorkbenchSize` tier for that viewport.

### 9.4 Dashboard Layout Registry (Required)
Formalize a registry that maps widgets/tools to supported density tiers so layouts never break on small screens.

**Each entry must include:**
- `id` + display name
- Supported tiers (`compact`, `regular`, `expanded`)
- Required panes (nav / center / inspector)
- Fallback behavior when a tier is unsupported (summary, compact card, or hidden)

**Example entries:**
- **Schedule Widget:** compact/regular/expanded (center only)
- **Notebook:** regular/expanded (center + inspector)
- **Notebook Compare:** expanded only (center + inspector)
- **Insights Panel:** regular/expanded (inspector)

**Rule:** If a widget is not supported at the current tier, it must gracefully downshift (summary) or be hidden—never clipped.

## 10) Visual Identity (Top-Level)

DormWay should feel like **high-performance clarity**, not a cheerful productivity carnival and not corporate enterprise software. It must be **fast to scan, calm under stress, and trustworthy**.

**Core Visual Metaphors:**
- Clarity over chaos.
- Noise-canceling focus (reduce friction, keep student in control).

**Avoid:**
- Overly trendy aesthetics that age fast.
- Heavy glass effects in dense content.
- Decorative gradients in data-heavy views.

## 11) Design System (Platform Details)

### 11.1 Color System

**Brand Accents (Electric):**
- Electric Violet: `#6b21ff`
- Hot Pink: `#ff5fa1`
- Vivid Orange: `#ff7b3f`

**Core Brand Tokens (Primary):**
- `--ds-primary-brand: #6366f1`
- `--ds-primary-soft: #818cf8`
- `--ds-primary-deep: #4f46e5`

**Semantic Colors:**
- Success: `#10b981`
- Warning: `#f59e0b`
- Error: `#ef4444`
- Info: `#3b82f6`

**Color Hierarchy Map (Required):**
- **Primary Brand Blue (`--ds-primary-brand`)**: navigation, primary CTAs, selected states.
- **Electric Accents**: reserved for product highlights (Ace moments, new notebook, key milestone).
- **Semantic Colors**: urgency and status only (due soon, overdue, success).
- **Course Colors**: user-defined tags. Never compete with Primary Brand Blue.

**Public Landing Theme (LockedIn):**
- Supports both **dark** and **light** variants; ensure contrast in both.
- Uses DS surface/text/border tokens.
- Primary CTA + accents use `--ds-primary-brand` and `--ds-primary-deep`.

**Usage Rules:**
- Course colors are accents (edges, dots, rings), not full fills.
- Numbers and labels must pass contrast (4.5:1).
- Use semantic colors for urgency, not decoration.

### 11.2 Themes

**Web:** System, Light, Dark, Glass (Landing). Dark is default for unauthenticated landing; dense surfaces use solid backgrounds.

**Product:** Solid surfaces over glass for primary content. Glass effects reserved for overlays or modals.

### 11.3 Typography

**Marketing / Brand:** Satoshi (primary marketing font).

**Product UI (Chrome / Dense):** System stack for speed and clarity.
- Sans: `-apple-system, BlinkMacSystemFont, "Inter", "SF Pro Display", system-ui, sans-serif`
- Mono: `"SF Mono", "JetBrains Mono", "Fira Code", "Consolas", monospace`

**Reading Surfaces (Notes / Long-form):** Lexend body stack for readability.
- Body: `"Lexend", -apple-system, BlinkMacSystemFont, "SF Pro Display", system-ui, sans-serif`

**Hierarchy (Product):**
- Brand headlines: display font, 600-700, tight line height.
- Body: 14-18px, line height ~1.6, neutral color.
- Labels: 12-14px, medium weight, high contrast.

### 11.4 Layout & Surfaces

**Principles:**
- Glance first, then scan, then act.
- Stable layout (no shifting alignment).
- Minimal text; use counts, icons, and short labels.

**Surfaces:**
- Primary content uses solid cards and subtle borders.
- Avoid per-cell shadows or heavy blurs in grids.

### 11.5 Motion

**Philosophy:** Physics over loops.

**Do:**
- Springy press feedback.
- Hover glows (subtle).
- Scroll reveal (staggered, optional).

**Don’t:**
- Constant looping motion.
- Pulsing CTAs.
- Auto-played distractions.

### 11.6 Data Visualization & Schedule

**Schedule UX Rules (Non-negotiable):**
- Color carries meaning, not decoration.
- Course color is an accent, not full background.
- If data is missing or uncertain, show placeholder or omit.

**Reference:** `Product/Design/LockedIn-Schedule-UX-Guidelines.md`

### 11.7 Geometry System (Precision Engineering)

**Purpose:** Provide a simple, repeatable geometry system so the UI feels intentionally engineered and visually consistent across light and dark modes.

**Core geometry rules:**
- **Primary ratio:** 1 : 1.25 (use for scaling type, spacing, and layout dimensions).
- **Base grid:** 4pt base with an 8pt dominant cadence (most vertical gaps land on 8pt).
- **Baseline grid:** 8pt grid for vertical rhythm; align headers, chips, and tables to this grid.
- **Spacing ladder (rounded to whole px):** 4, 8, 12, 16, 24, 32, 48, 64. Avoid one-off values.
- **Type scale (1.25 ratio, rounded):** 12, 15, 19, 24, 30, 38, 48, 60. Use 15–16 for body, 16–18 for cards, 20–24 for section headers.
- **Corner radii system:** R8 (chips / controls), R12 (cards / widgets), R20 (hero / primary surfaces). Avoid one-off radii.
- **Stroke weights:** 2px @ 24px icons, 2.5px @ 32–40px, 3px @ 48px+. No fractional weights.
- **Axis alignment:** Vertical stems or timeline lines must align to center axis and keep a **≥1px breathing gap** from borders or base lines.
- **Panel proportion (brand echo):** Use **9:10** or **8:9** aspect ratios for hero panels and visual tiles to subtly mirror the D‑Vault proportions.
- **Gradient discipline:** One direction for brand gradients (top-left → bottom-right). Avoid banding; use a single smooth sweep.

**Reference use cases:** app icon, schedule timelines, hero cards, icon containers.

### 11.9 Data Provenance Patterns

DormWay must show **where a deadline or task came from** (not just that it exists).

**Required pattern:**
- Source chip on every detail view (e.g., Canvas, Syllabus PDF, Email).
- Source details should include at least one of: **page number**, **document title**, **API source**, or **sync timestamp**.
- If provenance is uncertain, show an explicit **Needs Review** indicator.

**Example labels:**
- “Syllabus PDF · Page 4”
- “Canvas API · Updated 2h ago”
- “Email forward · Aug 28”

### 11.10 Trust Level Badges (Deterministic vs AI)

Every feature should advertise its trust mode so students know what is guaranteed.

**Badge modes:**
- **Deterministic** (rules-based, 100% reliable)
- **Assisted** (rules + heuristics, still deterministic output)
- **AI** (Ace or generative output)

**Rules:**
- Use a small chip in headers/footers, never large banners.
- Deterministic features get neutral tones; AI gets Electric accents.
- Trust badges must appear in any AI-generated response surface.

### 11.11 Empty States (DormWay Voice)

Empty states are the first impression of the Student OS.

**Rules:**
- Use “Helpful Upperclassman” voice and offer a single clear next action.
- Keep the layout calm: one headline, one sentence, one CTA.
- Use Electric accents sparingly for the CTA or icon only.

**Example copy:**
- “No deadlines yet. Drop a syllabus and I’ll build your timeline.”
- “This notebook is empty. Start with a quick outline.”

### 11.12 Accessibility & Contrast

**Minimum contrast:** 4.5:1 for body text (AA).

**Enforcement:**
- All new tokens must pass contrast against **surface-1** and **surface-2**.
- Use the `/dev/brandbook` live contrast panel before shipping visual changes.

## 12) Platform-Specific Guidance

### Web (LockedIn)
- Fast scanning, minimal text, clear hierarchy.
- Avoid glass in dense views.
- Always show next action above the fold on Today.

### iOS
- Short, frequent sessions; thumb-friendly actions.
- Information density must remain readable in 1-2 seconds.
- Use DS tokens for semantic color and typography hierarchy.

### Cross-Platform Interaction Symmetry (Required)
- If a priority level, status, or color is set on Web, its **visual encoding** must match on iOS.
- No “data-only parity.” Interaction hierarchy and visual emphasis should be consistent across platforms.
- Any intentional divergence must be documented in the platform notes.

## 14) Deterministic Intelligence (Precision Engineering)

DormWay is not just smart by LLMs. It is smart by design. We have **deterministic feature pillars** that deliver consistent, explainable value.

**Positioning Phrase:** Precision Engineering for student schedules.

**Deterministic Pillars:**
- **Smart Organize:** Rules-based prioritization and grouping (Do Now / Up Next / Due Soon).
- **Tidy Up:** De-duplication, schedule reconciliation, and clean timelines.
- **Conflict Detection:** Detect overlaps, heavy days, and hidden clashes before they hurt you.
- **Source Integrity:** Clear provenance from Canvas and syllabi (no mystery data).

**Brand Impact:** We are an Operating System with reliable, auditable mechanics—not just generative output.

## 15) Conflict Resolution Rules

When sources conflict:
1. **Public landing page phrasing:** current `dormway-lockedin` landing copy wins for public-facing pages (including Hypertune variants).
2. **Voice & Positioning:** Master Guide wins for non-landing copy and product surfaces.
3. **Product UX & visual rules:** Design Vision + UX Guidelines win.
4. **If conflict remains:** default to clarity, scanability, and student trust.

**Deprecated source:** `.repos/dormway-platform/services/marketing-site` (do not use for public copy or visuals).

**Known tension (resolved):**
- “Dark glass + electric accents” vs “noise-canceling clarity.”
- Resolution: Use dark/glass only where it improves focus, not as a visual gimmick. Clarity and scanability are always priority. The brand metaphor is about reducing noise, not about aesthetic darkness.
