# DormWay Growth Instrumentation Backlog

Date: 2026-02-22
Purpose: close attribution gaps and make GTM experiments decision-grade.

## Priority 0 (Scale Gate): Landing Upload Tracking

Problem:
- Landing uploader flow submits files but does not emit reliable upload start/completion events.
- This breaks attribution for the highest-intent homepage action.

Relevant code:
- `.repos/dormway-platform/services/dormway-lockedin/src/hooks/useMultiFileUpload.ts`
- `.repos/dormway-platform/services/dormway-lockedin/src/lib/amplitude.ts`
- `.repos/dormway-platform/services/dormway-lockedin/src/types/amplitude-events.ts`

Required implementation:
1. On submit start in `handleSubmit`, fire `landing_upload_started`.
2. On submit completion, fire `landing_upload_completed`.
3. Always include event properties:
- `source` (`landing_bootstrap`)
- `upload_method` (`drag_drop` | `file_picker` | `email`)
- `file_count`
- `syllabus_count`
- `schedule_count`
- `other_count`
- `detected_school`
- `success_count`
- `failure_count`
- `error_reason` (if failed)

Verification:
- Event fires in local/dev and production telemetry.
- Funnel reports can segment by upload method and source.

Gate rule:
- No scaled channel experiments until this is live and verified.

## Priority 1: Canonical KPI + Baseline Framework

Goal:
- Ensure one canonical WFAU/activation definition and baseline readout before interpreting lift.

Actions:
- Create canonical first-action derived flag per user in first 7 days.
- Build 2-week baseline by source and campus.
- For activation/retention rates, report point estimate + 95% CI.
- Set minimum practical effect thresholds for keep/kill calls.

Candidate first-action event set:
- `syllabus_uploaded`
- `schedule_imported`
- `onboarding_integration_connected`
- `setup_widget_syllabus_uploaded`

## Priority 2: Retention Horizons (D7 + D14 + W4)

Goal:
- Prevent overfitting to one weekly cycle.

Actions:
- Add D14 and W4 retention to the weekly scorecard.
- Define "active" as meaningful planning action (not passive open).
- Break retention down by source and campus.

## Priority 3: Referral Quality Attribution

Goal:
- Distinguish referral volume from referral quality.

Actions:
- Join `referral_completed` and referral deep links with first action, D14, and W4.
- Report quality by ambassador, campus, and campaign.
- Require retention parity before scaling referral incentives.

## Priority 4: Lifecycle Causal Readout

Goal:
- Measure whether lifecycle nudges improve behavior.

Actions:
- Tag Sunday preview and due-soon nudges with send identifiers.
- Compare Monday/Tuesday actives in exposed vs control cohorts.
- Report D14/W4 deltas for exposed cohorts.

## Priority 5: Trust Friction Instrumentation

Goal:
- Quantify trust blockers in acquisition and onboarding.

Actions:
- Track FAQ expansions/clicks for:
  - "How do you make money?"
  - "Is my data safe?"
- Track drop-off after trust-critical surfaces.
- Add trust-friction panel to weekly dashboard.

## Definition of Done
- Landing upload attribution is visible and trusted in dashboards.
- WFAU and activation are computed from one documented event definition.
- D7, D14, and W4 are reported weekly by source and campus.
- Experiment readouts include confidence intervals, not raw lift claims.
- Referral and lifecycle channels are evaluated on quality, not clicks.
