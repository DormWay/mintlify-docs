# GTM Operating Contract - Single Thread (Current)

## Purpose
Create one clear operating system for a 2-person team so execution stays focused and old plans stop competing with current work.

## Active Execution Thread (Use These Only)
If work is not grounded in these docs, it is not in active execution:

1. [GTM Playbook - Spring 2026 (Current)](/docs/product/go-to-market/gtm-playbook-spring-2026-current)
2. [GTM 4-Week Execution Calendar - Spring 2026](/docs/product/go-to-market/gtm-4-week-execution-calendar-spring-2026)
3. [GTM Copy Bank - Spring 2026](/docs/product/go-to-market/gtm-copy-bank-spring-2026)
4. [GTM Instrumentation Backlog - Spring 2026](/docs/product/go-to-market/gtm-instrumentation-backlog-spring-2026)
5. [GTM Agentic Implementation Addendum - Spring 2026 (Current)](/docs/product/go-to-market/gtm-agentic-implementation-addendum-spring-2026-current)

Everything else in `Product/Go-to-Market/` is reference unless explicitly promoted.

## 2-Person Focus Rules
1. One scoreboard: WFAU, activation, D14, W4.
2. One primary bet at a time per week.
3. No net-new channel scale until instrumentation gate passes.
4. Any idea that takes more than 2-3 days or needs new surface area starts as `status: draft`.
5. Trust and copy guardrails are blocking, not optional.

## Old vs New Doc Lifecycle
Use only these statuses:

1. `draft` = not approved for active execution
2. `current` = approved and executable now
3. `deprecated` = replaced by a newer current doc
4. `archived` = historical snapshot only

### Promotion Rule (`draft` -> `current`)
Promote only when:
1. Owner is explicit
2. Success metric is explicit
3. Decision date exists
4. It does not conflict with the active execution thread above

### Replacement Rule (`current` -> `deprecated`)
When replacing a current doc:
1. Set `status: deprecated`
2. Add `superseded_by: <new current doc link>`
3. Add `superseded_on: YYYY-MM-DD`
4. Add one line at top: `Deprecated - use <new current doc link>`

### Retirement Rule (`deprecated` -> `archived`)
Archive after 30+ days with no active dependency.

## Conflict Resolution (Fast)
When two docs disagree:

1. The newer `status: current` doc wins.
2. If both are `current`, this order wins:
   1. Playbook
   2. 4-Week Calendar
   3. Instrumentation Backlog
   4. Copy Bank
3. Resolve conflict same day and deprecate the loser.

## Weekly Hygiene Ritual (15 min, Friday)
1. Confirm only 1-2 docs are being actively executed.
2. Demote stale "used-to-be current" docs to `deprecated`.
3. Ensure every new idea doc remains `draft`.
4. Update `last_updated` on active current docs touched that week.

## Current 4-Week Direction (Summary)
1. Campus density + setup quality over channel sprawl.
2. Short-form as feeder, not vanity.
3. Lifecycle nudges tied to behavior, not spam.
4. SEO remains support work, not primary engine during this cycle.
