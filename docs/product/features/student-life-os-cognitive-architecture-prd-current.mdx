# Student Life OS - Cognitive Architecture PRD (Current)

This is the consolidated, build-ready PRD for DormWay as a Student Life Operating System. It combines:

1. Learning-science foundations (retrieval, spacing, interleaving, generation).
2. Temporal distinctness design (routine blur mitigation via event boundaries).
3. MVP + MVO execution spec for immediate launch.
4. Gen Z retention layer (admin shielding, hidden-curriculum navigation, identity growth, social accountability, financial utility).

This document is the product execution bridge for v1.0 and near-term v1.1-v1.3 planning.

## 1) Product Goal and Success Definition

### Goal

Reduce:

1. **Knowledge decay** from passive restudy and cramming.
2. **Routine blur** (subjective time compression from repetitive weeks).

### Success Definition

DormWay becomes a daily-use OS when students perceive it as:

1. A cognitive scaffold that improves recall.
2. A practical life layer that reduces admin and executive burden.
3. A system that feels emotionally safe, fast, and personally relevant.

## 2) Scientific Evidence Stack (Product Contract)

| Mechanism | Evidence Tier | Typical Effect | Product Implementation |
|---|---|---|---|
| Spacing / distributed practice | Strong | d = 0.54 to 0.85 | Recall scheduling at `t+0`, `t+2d`, `t+7d` (later `t+30d`) |
| Retrieval practice / testing effect | Strong | g = 0.18 to 0.50 | Save Points + Recall Feed |
| Interleaving | Moderate | Domain-dependent | Cross-course mixed recall cards |
| Generation effect | Strong | Variable (meta-analytic support) | Student-generated summaries/questions |
| Event segmentation theory | Strong framework + empirical support | N/A | Post-class ritual as event boundary |
| Context-dependent memory | Moderate | Stronger in low-frequency contexts | Optional location-tagged cues |
| Implementation intentions | Moderate to strong | up to d = 0.99 in some groups | If-then trigger design around class/deadline cues |
| Cognitive load management | Strong | N/A | Micro-chunk sessions with purposeful pause |

### Claims Guardrails

Safe:

1. Supports durable learning habits and recall.
2. Helps reduce routine blur through structured reflection.
3. Scaffolds task initiation and planning.

Not allowed:

1. Guarantees high grades.
2. Treatment claims for ADHD.
3. "Cures time blindness."

## 3) MVP Scope (6 Weeks)

The 6-week MVP includes three core features plus analytics.

## 3.1 Feature A: Post-Class Save Point

### Intent

Create intentional event boundaries and immediate generative retrieval right after class.

### Trigger

Calendar-synced class end.

### Required UX

1. One sentence summary.
2. Three keywords.
3. One self-test question.

### User Story

As a student, I want a low-friction post-class recap so each class feels distinct and key ideas persist.

### Acceptance Criteria

1. Median completion time `<45s`.
2. Completion rate captured by course and time-of-day.
3. Self-test question automatically seeds recall queue.

## 3.2 Feature B: Spaced Recall Feed

### Intent

Move material from familiarity to durable retrieval.

### Intervals

`t+0`, `t+2d`, `t+7d` (add `t+30d` post-MVP).

### Required UX

1. Vertically scrolling cards.
2. Self-rating (`1-5`) before reveal.
3. Reveal answer with immediate feedback for `t+0`.

### User Story

As a student, I want prompts at the right times so I can retain material without cramming.

### Acceptance Criteria

1. Interleaving across active classes by default.
2. Immediate corrective feedback on same-day cards.
3. Completion + self-rating logged for every card.

## 3.3 Feature C: Class Modes (Disciplinary Templates)

### Intent

Match retrieval prompts to disciplinary cognition.

### Modes

1. `STEM`: procedural reasoning, strategy choice, problem discrimination.
2. `Humanities`: synthesis, argumentation, counter-argument, interpretation.

### User Story

As a student, I want prompt styles aligned to class type so recall sessions feel useful and authentic.

### Acceptance Criteria

1. Per-class mode configuration.
2. Template sets differ by mode.
3. Feed interleaving respects mode context.

## 4) MVO Addendum (Ship-Now Cognitive Rituals)

## 4.1 3-2-1 Save Point (Writing-to-Learn)

Use:

1. `3` things learned.
2. `2` things to learn more about.
3. `1` muddiest-point question.

Acceptance criteria:

1. Median completion `<45s`.
2. At least 80% of entries include all fields.
3. Muddiest question auto-converted to a recall card.

## 4.2 Metacognitive Wrappers

Lecture wrapper:

1. Pre-class: "What are today's goals?"
2. Post-class: "What will I remember in 5 years?"

Assignment wrapper:

1. "What strategy worked?"
2. "Where am I still confused?"

Acceptance criteria:

1. Wrapper completion logged.
2. Reflections included in weekly recap.

## 4.3 Situated Retrieval Cues (Opt-In)

Trigger: stationary point `>15 min` within ~50m.

Behavior: if a location is course-tagged, trigger short contextual recall prompt.

Acceptance criteria:

1. Explicit opt-in only.
2. Manual tagging fallback always available.
3. Compare contextual nudge completion against non-context baseline.

## 4.4 Micro-Pause Study Blocks

Default cycle: `10-15 min` focus + `2 min` purposeful pause.

Acceptance criteria:

1. One-tap start from recall/feed/dashboard.
2. Session adherence and completion logged.
3. No high-friction interruptive flow.

## 4.5 Visual Time Anchors

1. Shrinking-wedge timer.
2. Backward planning: due date -> buffer -> start-now date.

Acceptance criteria:

1. Every tracked deadline has derived start-now date.
2. Dashboard surfaces overdue start-now tasks.

## 5) Psychological Bridge Layer (Phased, Post-MVP)

This layer turns DormWay from a study utility into a daily identity-and-life operating system.

## 5.1 Bureaucracy Buffer (Administrative Shield)

Research lens: campus bureaucracy and "psychological erosion" pressure patterns.

Problem: admin email overload and low-signal complexity.

Build:

1. Admin triage surface summarizing obligations as `Event -> Response -> Outcome`.
2. Prioritized deadlines and required actions only.
3. Consequence framing for each action (what happens if ignored).

Metric:

1. Missed admin deadline reduction.
2. Time-to-action reduction for administrative tasks.

## 5.2 Hidden Curriculum Navigator (Pro-Nudges)

Research lens: hidden-curriculum and cultural-capital gaps.

Problem: students miss opportunity pathways because unwritten rules are invisible.

Build:

1. Office hours, department events, and advising windows become "Pro-Nudges."
2. Nudge template provides tactical script (what to ask, why it matters, next step).
3. Track "capital actions" (office-hour visit, lab inquiry, recommendation prep).

Metric:

1. Pro-Nudge open and action rates.
2. Opportunity conversion events (meeting booked, follow-up sent, application started).

## 5.3 Identity Arc Dashboard (Main Character Mode)

Research lens: identity-first habit design.

Problem: tasks feel disconnected from future-self outcomes.

Build:

1. Student selects identity arc (for example, "Aspiring Data Scientist").
2. Save Points and recall actions are tagged as "votes" for that identity.
3. Visual growth track shows identity-consistent streaks and competency progression.
4. Optional "Main Character" framing for students who prefer persona-led motivation language.

Metric:

1. Identity-tagged action ratio.
2. 7-day and 30-day retention lift for identity-on cohorts.

## 5.4 Skill Ledger (Digital Portfolio Pipeline)

Research lens: externalized memory and expression-first learning workflows.

Problem: effort disappears after studying; students cannot reuse it for career narrative.

Build:

1. Convert Save Points and writing-to-learn entries into skill artifacts.
2. Weekly auto-generated "Skill Ledger" recap (skills, evidence, project ideas).
3. One-tap draft export to resume/LinkedIn/portfolio notes.

Metric:

1. Weekly artifact generation rate.
2. Export engagement rate.

## 5.5 Quiet Companionship (Lo-Fi Focus Rooms / Body Doubling)

Research lens: co-action and low-toxicity social accountability.

Problem: isolation and low-accountability solo work.

Build:

1. Camera optional, mics-off default focus rooms.
2. Lo-fi study ambiance with low social pressure.
3. Presence-first UX (minimal chat, minimal performance signaling).
4. "Quiet companionship" defaults over social engagement mechanics.

Metric:

1. D7 and D30 repeat session rates.
2. Completion lift vs solo focus sessions.

## 5.6 Financial Utility Layer

Problem: persistent day-to-day financial stress.

Build:

1. Schedule-aware bill reminders.
2. Contextual student discount surface.

Metric:

1. Missed bill reduction.
2. Offer view/redeem rates.

## 5.7 Digital Sanctuary UX Contract

1. Low tap count on core flows.
2. Dark mode support.
3. Personalizable themes.
4. Visual language that avoids institutional "school portal" feel.
5. Calm information density and low-cortisol interaction patterns on high-stress surfaces.

## 6) Non-Negotiable Functional Constraints

1. Save Point completion median `<45s`.
2. One-tap deferral (`10 min`, `After Dinner`, `Tomorrow`).
3. Immediate corrective feedback on `t+0` recall cards.
4. Privacy-first defaults and explicit consent controls for contextual sensing.
5. No manipulative reward mechanics.

## 8) Validation Plan

## 8.1 MVP Pilot (2-3 Weeks)

Design:

1. Treatment: DormWay active in two courses.
2. Control: normal methods.

Outcomes:

1. Delayed recall quiz.
2. Perceived passage-of-time score.
3. Habit adherence (`>=4` Save Points/week).

Power target:

1. ~`N = 128` for medium effect (`d = 0.5`), split `64/64`.

## 8.2 Longitudinal Follow-Up (8-12 Weeks)

Outcomes:

1. Midterm/final performance trends.
2. Executive function self-report deltas.
3. Habit persistence beyond onboarding.

2. `v1.2`: Quiet Companion + Financial Utility.

## 10) Key Risks and Mitigations

| Risk | Mitigation |
|---|---|
| Notification fatigue | Adaptive cadence + one-tap deferrals + quiet windows |
| Input friction | Strict low-latency input constraints + low typing requirements |
| Error reinforcement | Mandatory immediate feedback on same-day retrieval |
| Privacy concerns | Opt-in contextual sensing + transparent controls |
| Scope creep | Phase gate by retention and completion metrics |
