# Dev Environment Setup

DormWay's preferred backend and web development setup runs Docker on a remote Hetzner VM instead of your laptop. Your local checkout remains the source of truth, Mutagen mirrors files to the VM, and SSH tunnels bring the stack back to `localhost`.

## What This Setup Gives You

- Same localhost ports as local Docker, but lower battery and memory pressure
- Faster full-stack iteration across `api-router`, `engine`, `lockedin`, `admin`, and supporting services
- HTTPS on your own `dev-<name>.dormway.app` subdomain for device testing

## Architecture

```text
Your Mac
  -> local repo checkout
  -> Mutagen two-way sync
  -> SSH tunnels to localhost

Hetzner VM
  -> Docker services
  -> Doppler auth and config
  -> Caddy for HTTPS
  -> Dozzle for logs
```

## Prerequisites

- macOS with Homebrew
- SSH key at `~/.ssh/id_ed25519`
- Hetzner Cloud account
- Local checkout of `dormway-beta-workspace`
- Doppler access for your dev config

## One-Time Setup

### 1. Create the VM and DNS

- Hetzner Ubuntu 22.04 server, usually `CPX31`
- Open ports `22`, `80`, `443`, `8443`
- Add `dev-YOURNAME.dormway.app -> YOUR_VM_IP`

### 2. Configure SSH

```bash
mkdir -p ~/.ssh/sockets
```

Add a `Host dev-vm` entry to `~/.ssh/config` with your VM IP, root user, and `ControlMaster` settings so Mutagen does not trip connection limits.

```bash
ssh dev-vm 'echo "Connected!"'
```

### 3. Provision the VM

From the workspace root:

```bash
DEV_DOMAIN=dev-YOURNAME.dormway.app ssh dev-vm 'bash -s' < scripts/remote-dev/setup-vm.sh
```

This installs Docker, Node, Doppler CLI, Dozzle, and Caddy.

### 4. Configure Doppler on the VM

Recommended:

```bash
doppler configs tokens create --project dormway --config dev_YOURNAME --name "dev-vm-$(date +%s)" --plain
ssh dev-vm "echo 'DOPPLER_TOKEN=dp.st.YOUR_TOKEN_HERE' > ~/dormway-platform/.doppler_token"
ssh dev-vm "cd ~/dormway-platform && doppler configure set project dormway && doppler configure set config dev_YOURNAME"
```

Verify:

```bash
ssh dev-vm 'cd ~/dormway-platform && doppler secrets get DATABASE_URL --plain | head -c 20'
```

### 5. Install Mutagen and local config

```bash
brew install mutagen-io/mutagen/mutagen
mutagen daemon start
cp scripts/remote-dev/remote-dev.env.example .remote-dev.env
```

Set at least:

```text
REMOTE_DEV_HOST=YOUR_VM_IP
REMOTE_DEV_USER=root
REMOTE_DEV_SSH_KEY=~/.ssh/id_ed25519
REMOTE_DEV_DOMAIN=dev-YOURNAME.dormway.app
```

### 6. Start the stack

```bash
make remote-dev
```

On first run, build `dormway-core` on the VM:

```bash
ssh dev-vm 'cd ~/dormway-platform/services/shared/dormway-core && npm ci --ignore-scripts && npm run build'
make remote-dev-restart s=api-router
make remote-dev-restart s=engine
make remote-dev-restart s=ably-relay
```

### 7. Enable HTTPS

```bash
ssh dev-vm 'systemctl start caddy && systemctl enable caddy'
curl -s -o /dev/null -w "%{http_code}" https://dev-YOURNAME.dormway.app/health
```

## Daily Workflow

```bash
make remote-dev
make remote-dev-status
make remote-dev-logs s=engine
make remote-dev-restart s=api-router
make remote-dev-stop
```

## Hot Reload Rules

<Warning>
  `dormway-lockedin` and `dormway-admin` should hot reload without container restarts. Restart backend services when their code or shared build outputs change.
</Warning>

## Current Sharp Edge

The latest Riley-state note still records a `dormway-lockedin` crash loop caused by Sentry config files not being visible inside the container even though they exist on the VM host. If a fresh remote-dev setup shows the same symptom, inspect container mounts and rebuild or prune the lockedin container state before debugging app code.
