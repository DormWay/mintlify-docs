# Frontend: LockedIn (Next.js)

`dormway-lockedin` is the student-facing Next.js web application. It runs on port 3008.

**Service path:** `services/dormway-lockedin/`

## Hot Reload — Never Restart

<Warning>
  **dormway-lockedin uses Turbopack and hot reloads automatically.** Never restart the container after code changes. Restarting is slow (30-60s) and unnecessary. Only restart for dependency changes, environment variable changes, or config file changes.
</Warning>

## File Edit Rules

<Warning>
  **Always use `Write` (not multiple `Edit` calls) for dormway-lockedin files.**

  Every filesystem write triggers Turbopack. Multiple sequential edits = multiple filesystem events = cache corruption risk. A single `Write` is atomic and safe.

  Process: Read the full file → make all changes mentally → write the complete new version in one tool call.
</Warning>

This applies even for a single small change. Turbopack can pick up an intermediate (truncated) file state between Edit calls and cache a malformed parse, requiring a container restart.

## Component Discovery — Search Before Assuming

<Warning>
  **Always search for the exact UI text before assuming a component name.** Components are often named differently from their apparent function.
</Warning>

```bash
# Find the component that shows "Ask a question" menu
grep -r "Ask a question" services/dormway-lockedin/src/components/

# Find all modal components
grep -r "createPortal" services/dormway-lockedin/src/components/

# List available UI primitives
ls services/dormway-lockedin/src/components/ui/
```

**Real example:** A floating action button showing "Ask a question", "Share Feedback", "Take notes" menu is `AceChatBubble.tsx` — not `AceFAB.tsx`. Searching for the exact text finds the right file instantly.

## Modal Pattern (createPortal)

dormway-lockedin modals use `createPortal` + a custom overlay — not shadcn Dialog. Reference: `GenericUploadModal.tsx`.

```typescript
import { createPortal } from 'react-dom';
import { useState, useEffect } from 'react';

export function MyModal({ open, onClose }: { open: boolean; onClose: () => void }) {
  const [mounted, setMounted] = useState(false);

  useEffect(() => {
    setMounted(true);
  }, []);

  if (!open || !mounted) return null;

  const modal = (
    <div className="fixed inset-0 z-50 flex items-center justify-center p-4">
      {/* Backdrop */}
      <div
        className="fixed inset-0 bg-black/60 backdrop-blur-sm"
        onClick={onClose}
      />
      {/* Modal Content */}
      <div className="relative z-10 w-full max-w-lg rounded-2xl bg-[var(--ds-surface-1)] border border-[var(--ds-border-1)] shadow-2xl">
        {/* your content */}
      </div>
    </div>
  );

  return createPortal(modal, document.body);
}
```

## Quick Overlay Focus Theft Prevention

When using `useOverlayLifecycle`, the options object **must** be memoized:

```typescript
// ✅ CORRECT — memoized options prevent re-renders
const lifecycleOptions = useMemo(() => ({
  onOpen: handleOpen,
  onClose: handleClose,
}), [handleOpen, handleClose]);

useOverlayLifecycle(lifecycleOptions);

// ❌ WRONG — inline object causes re-renders → focus theft
useOverlayLifecycle({ onOpen: handleOpen, onClose: handleClose });
```

## No Browser Alerts

Never use browser dialogs in dormway-lockedin:

```typescript
// ❌ NEVER use these
window.alert('message');
window.confirm('Are you sure?');
window.prompt('Enter value');

// ✅ Use confirm-dialog for confirmations
import { ConfirmDialog } from '@/components/ui/confirm-dialog';

// ✅ Use notify for simple messages
import { notify } from '@/lib/notify';
notify('Operation complete');
```

## Importing from API Router

dormway-lockedin fetches data via the API router on port 3001 locally, or through the Zuplo gateway in production. Use the configured `apiClient` or `fetch` with the appropriate base URL from env vars.

```typescript
// API calls use NEXT_PUBLIC_API_BASE_URL
const response = await fetch(`${process.env.NEXT_PUBLIC_API_BASE_URL}/v2/students/me/courses`);
```
