# DormWay Quality Gates

Ship/no-ship rules for student-facing work. Every gate is blocking — if it fails, the work does not ship until fixed.

## 1. Trust Gate

Does this create or break student trust?

- No overclaiming (grades, automation, AI capabilities)
- No contradictions between landing, onboarding, lifecycle, FAQ, and pitch
- Data access claims match actual implementation
- "We use AI for dates, not essays" boundary is respected
- If students might worry about something (data, money, security), address it proactively

## 2. First-Value Gate

Can a new student get value fast?

- First meaningful action (syllabus upload, schedule import, or Canvas connect) is obvious and reachable
- No unnecessary steps between signup and first value
- No ambiguous branching that creates confusion about what to do first
- Time-to-first-value does not increase

## 3. Copy & Expectation Gate

Does the copy match what the product actually does?

- No banned language (see [DormWay-Brand-Voice-and-Positioning-Master-Guide](/docs/product/brand/dormway-brand-voice-and-positioning-master-guide) banned list)
- Passes the Riley Test (friend test, authenticity test, jargon test, problem-first test, humility test, transparency test)
- Public promises match current product reality
- Monetization language is consistent everywhere

## 4. UX Sharp-Edge Gate

Will this confuse or frustrate a first-time user?

- No state where a student doesn't know what to do next
- No surface that feels unfinished, broken, or placeholder
- No flow that creates "scam vibes" or erodes confidence
- Loading states, empty states, and error states are handled

## 5. Analytics & Canon Gate

Is this grounded in current canonical docs and instrumented?

- Metric definitions match [GTM Playbook - Spring 2026 (Current)](/docs/product/go-to-market/gtm-playbook-spring-2026-current)
- Source attribution is in place before scaling any channel
- No strategic assumptions from draft or deprecated docs treated as committed
- Instrumentation exists to measure whether this change helped or hurt

## 6. Consistency Gate

Does this contradict anything already live?

- No conflicting messaging across surfaces
- No feature that promises something another surface contradicts
- No UX pattern that breaks expectations set elsewhere in the product

## 7. Two-Founder Operational Gate

Can Riley and Ethan actually operate this?

- Does not require a team they don't have
- Does not create ongoing management overhead disproportionate to value
- Does not depend on manual ops that will break when attention shifts
- Can be maintained, monitored, and iterated by two people through August 2026

## How To Use

Before shipping any student-facing work:

1. Run through each gate
2. If any gate fails, fix before shipping
3. If a gate is ambiguous, flag it — don't silently ship
