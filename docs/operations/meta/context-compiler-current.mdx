# Context Compiler

Task-shaped context packet generator for DormWay agents.

## How To Use

After reading the startup sequence (Executive Context, Canon Map, Quality Gates), identify your task type below. Read the recipe for that type before starting domain work. If your task spans multiple types, combine recipes using the composition rules at the bottom.

## Task Types

### 1. Fundraising

**Trigger:** Any task producing investor-facing text, data claims, positioning statements, deck sections, outreach emails, or diligence materials.

**Must-read (in order):**
1. [Fundraising Narrative (Current)](/docs/plans/fundraising-narrative-current) — canonical investor story and proof structure
2. [DormWay-Brand-Voice-and-Positioning-Master-Guide](/docs/product/brand/dormway-brand-voice-and-positioning-master-guide) — voice, positioning, banned patterns
3. [GTM Playbook - Spring 2026 (Current)](/docs/product/go-to-market/gtm-playbook-spring-2026-current) — Section 2 (Non-Negotiables), Section 7 (KPI Definitions), Section 10 (Messaging Matrix)
4. [DormWay Framing Guardrails (Current)](/docs/product/brand/dormway-framing-guardrails-current) — anti-framing, AI language rules, banned patterns

**Check if relevant:**
- [Class of 2030 Workback Plan - March to August 2026 (Draft)](/docs/product/go-to-market/class-of-2030-workback-plan-march-to-august-2026-draft) — directional context for timeline and phasing. **Status: draft.** Do not present draft content as committed strategy in investor materials.

**Canonical claims in scope:**
- Core promise: "Never wonder what's due."
- AI boundary: "We use AI for dates, not essays."
- Monetization: "Free for students" (at the core level). Not "free forever." Paid plans are for org/admin and institutional pilots.
- First-action: syllabus upload, schedule import, or Canvas connect.
- Cohort: Class of 2030 freshman wedge.
- Timing: lead path by mid-May 2026, close by June 2026.

**Escalation triggers:**
- Any modification to core positioning, trust claims, or monetization language — stop and check with Riley.
- Any data claim that is not currently measurable — do not include.

**Quality gates:**
- Trust Gate — no overclaiming
- Copy & Expectation Gate — promises match product reality
- Consistency Gate — no contradiction across surfaces

**What matters most:**
Investor materials tell a story grounded in quality retention in a dense freshman cohort. Lead with founder-market fit and product love, not top-of-funnel volume. Every claim must be currently true and currently measurable. The fundraising story is about user love and repeatable distribution, not inflated numbers.

### 2. Student-Facing Copy

**Trigger:** Any text students will see — landing page, onboarding, notifications, emails, in-app messaging, social captions, lifecycle nudges.

**Must-read (in order):**
1. [DormWay Framing Guardrails (Current)](/docs/product/brand/dormway-framing-guardrails-current) — primary framing, anti-framing, voice rules, AI language rules, banned patterns, Riley Test
2. [DormWay-Brand-Voice-and-Positioning-Master-Guide](/docs/product/brand/dormway-brand-voice-and-positioning-master-guide) — full brand system
3. [GTM Copy Bank - Spring 2026](/docs/product/go-to-market/gtm-copy-bank-spring-2026) — approved copy patterns by surface

**Check if relevant:**
- [GTM Playbook - Spring 2026 (Current)](/docs/product/go-to-market/gtm-playbook-spring-2026-current) — Section 10 (Messaging Matrix by Funnel Stage) if the copy maps to a specific funnel stage
- [Onboarding Canon (Current)](/docs/product/onboarding-canon-current) — if the copy appears in the first-run experience

**Canonical claims in scope:**
- Core promise: "Never wonder what's due."
- AI boundary: "We use AI for dates, not essays."
- Monetization: "Free for students" (at the core level).

**Banned patterns (abbreviated — see Framing Guardrails for full list):**
- Corporate buzzwords: synergize, optimize, leverage, paradigm, ecosystem, holistic, next-gen, revolutionary, disruptive, game-changer, cutting-edge, comprehensive
- Overclaiming: anything implying DormWay writes essays, does homework, guarantees grades, or replaces studying
- AI marketing: AI-powered, intelligent assistant, digital companion, AI study buddy
- Vague promises: "optimize your semester," "command center," "autopilot"
- Monetization drift: "free forever" or "no premium tiers"

**Escalation triggers:**
- Any copy touching the canonical claims above — Riley review required.
- Any new AI-related language — verify against AI boundary.

**Quality gates:**
- Trust Gate — no overclaiming, data claims match implementation
- Copy & Expectation Gate — Riley Test (friend, authenticity, jargon, problem-first, humility, transparency)
- Consistency Gate — no conflicting messaging across surfaces

**What matters most:**
Student copy must sound like a real student wrote it. Lead with pain, not features. Specific scenarios over abstract benefits. If a friend wouldn't send this, rewrite it.

### 3. Onboarding

**Trigger:** Any task that modifies the sign-up flow, onboarding steps, first-run experience, or post-signup orientation.

**Must-read (in order):**
1. [Onboarding Canon (Current)](/docs/product/onboarding-canon-current) — first-run principles, first-value definition, trust constraints, what should never happen
2. [DormWay Quality Gates (Current)](/docs/operations/meta/dormway-quality-gates-current) — Trust, First-Value, UX Sharp-Edge, and Copy gates specifically
3. [DormWay Framing Guardrails (Current)](/docs/product/brand/dormway-framing-guardrails-current) — copy constraints for onboarding surfaces
4. [GTM Playbook - Spring 2026 (Current)](/docs/product/go-to-market/gtm-playbook-spring-2026-current) — Section 1 (first-action definition), Section 8 (instrumentation checklist)

**Check if relevant:**
- [Class of 2030 Workback Plan - March to August 2026 (Draft)](/docs/product/go-to-market/class-of-2030-workback-plan-march-to-august-2026-draft) — Onboarding Canon's current priorities section is sourced from this draft. **Verify with Riley before treating priorities as committed scope.**

**Canonical claims in scope:**
- First-action: syllabus upload, schedule import, or Canvas connect. Any one counts.
- Core promise: "Never wonder what's due."
- AI boundary: "We use AI for dates, not essays." — must be visible.
- Monetization: "Free for students."

**Code entry points:**
- `services/dormway-lockedin/src/pages/onboarding/`
- `services/dormway-lockedin/src/app/`
- `services/dormway-lockedin/src/contexts/`
- `services/dormway-lockedin/src/hooks/`

**Escalation triggers:**
- **All onboarding changes require Riley approval before shipping.** This is a hard stop, not a suggestion.
- Any change that increases time-to-first-value.
- Any change that adds steps between signup and first action.

**Quality gates:**
- First-Value Gate — first action obvious and reachable, no unnecessary steps
- Trust Gate — no overclaiming, data access claims match implementation
- UX Sharp-Edge Gate — no dead ends, no confusion about what to do next
- Copy & Expectation Gate — Riley Test passes

**What matters most:**
Onboarding exists to get a student to first value fast with zero confusion. Every change must preserve or reduce time-to-first-value. The escalation trigger is not optional. Riley owns the first-run experience.

### 4. GTM Experiment

**Trigger:** Proposing or executing a growth experiment — channel test, copy test, ambassador program change, lifecycle experiment, referral flow test.

**Must-read (in order):**
1. [GTM Playbook - Spring 2026 (Current)](/docs/product/go-to-market/gtm-playbook-spring-2026-current) — full doc, especially Section 3 (locked decisions), Section 7 (KPI definitions), Section 11 (experiment backlog)
2. [GTM Operating Contract - Single Thread (Current)](/docs/product/go-to-market/gtm-operating-contract-single-thread-current) — focus rules, active execution thread, conflict resolution
3. [GTM 4-Week Execution Calendar - Spring 2026](/docs/product/go-to-market/gtm-4-week-execution-calendar-spring-2026) — current weekly priorities

**Check if relevant:**
- [GTM Instrumentation Backlog - Spring 2026](/docs/product/go-to-market/gtm-instrumentation-backlog-spring-2026) — if the experiment requires new instrumentation
- [GTM Copy Bank - Spring 2026](/docs/product/go-to-market/gtm-copy-bank-spring-2026) — if the experiment involves copy variants
- [GTM Agentic Implementation Addendum - Spring 2026 (Current)](/docs/product/go-to-market/gtm-agentic-implementation-addendum-spring-2026-current) — if the experiment involves agent-assisted execution

**Canonical claims in scope:**
- Core promise: "Never wonder what's due."
- Monetization: "Free for students."
- AI boundary: "We use AI for dates, not essays."

**Key constraints:**
- Instrumentation gate: no scaled channel experiments until landing upload attribution is verified in dashboards.
- Focus rules: one primary bet per engine per week. Three bets max total.
- Source tagging: every experiment must be source-tagged with a kill criterion.
- Quality over volume: quality of first actions matters more than signup count.

**Escalation triggers:**
- Any experiment that would scale a channel before the instrumentation gate passes.
- Any experiment requiring new student-facing surface area (starts as `status: draft`).
- Any experiment that takes >2-3 days or needs new surface area.

**Quality gates:**
- Analytics & Canon Gate — metric definitions match Playbook, source attribution in place
- Trust Gate — no expectation breaks from overclaiming
- Two-Founder Operational Gate — can Riley and Ethan operate this

**What matters most:**
Every experiment must be source-tagged, have an explicit kill criterion, and fit within the weekly bet constraint. No vanity metrics. No channel scale before attribution is trusted. Campus density and first-action quality over national spread.

### 5. Strategy Review

**Trigger:** Evaluating a proposal, reviewing progress against strategy, answering "should we do X?", or auditing alignment between current work and committed strategy.

**Must-read (in order):**
1. [DormWay Executive Context (Current)](/docs/operations/meta/dormway-executive-context-current) — decision filter (the five questions)
2. [GTM Operating Contract - Single Thread (Current)](/docs/product/go-to-market/gtm-operating-contract-single-thread-current) — active execution thread, focus rules
3. Domain-specific `status: current` doc(s) relevant to the proposal

**Check if relevant:**
- [Class of 2030 Workback Plan - March to August 2026 (Draft)](/docs/product/go-to-market/class-of-2030-workback-plan-march-to-august-2026-draft) — useful for timeline context but **status: draft**. Do not treat as committed execution plan.
- [Fundraising Narrative (Current)](/docs/plans/fundraising-narrative-current) — if the proposal affects fundraising positioning or timing.

**Decision filter (apply to every proposal):**
1. Does this improve first value?
2. Does this improve trust?
3. Does this improve retention?
4. Does this increase freshman density in a target cohort?
5. Can Riley and Ethan realistically operate it through August?

**Key constraints:**
- Active execution thread: if work is not grounded in the 5 GTM execution docs, it is not in active execution.
- Any idea >2-3 days or requiring new surface area starts as `status: draft`.
- Trust and copy guardrails are blocking, not optional.
- Explicit cut list exists in Workback Plan (draft) — reference for what has already been de-prioritized.

**Escalation triggers:**
- Proposal contradicts the active execution thread.
- Proposal involves changing metric definitions.
- Proposal requires scaling before instrumentation gate passes.

**Quality gates:**
- Two-Founder Operational Gate — primary gate for strategic decisions
- Analytics & Canon Gate — are claims grounded in canonical sources?

**What matters most:**
If a proposal doesn't improve first value, trust, retention, or freshman density, and two people can't operate it through August, don't do it now. The right growth story is quality retention in a dense cohort, not feature sprawl or channel sprawl.

**Trigger:** Feature work, bug fixes, architecture changes, service modifications, database changes.

**Must-read (in order):**
1. Relevant service CLAUDE.md (e.g., `.repos/dormway-platform/CLAUDE.md`)
2. [Source of Truth Index](/docs/engineering/architecture/source-of-truth-index) — find the canonical engineering SoT for the domain

**Check if relevant:**
- [DormWay Quality Gates (Current)](/docs/operations/meta/dormway-quality-gates-current) — if the change is student-facing
- [DormWay Framing Guardrails (Current)](/docs/product/brand/dormway-framing-guardrails-current) — if the change involves copy or messaging
- [Onboarding Canon (Current)](/docs/product/onboarding-canon-current) — if the change touches the first-run flow

**Key constraints:**
- Prior Art Audit is mandatory before proposing new types, helpers, or systems. Run `./scripts/prior-art.sh "term"` or search all service directories.
- For engineering/implementation, code wins over docs. If a doc says "X" but code does "Y", trust the code.
- Hot reload: dormway-lockedin and dormway-admin hot reload. Engine and api-router require restart.
- Database: always use `DATABASE_URL_ADMIN` via Doppler with `bash -c`. Never raw connection strings.
- Check APIv2 endpoints before writing raw SQL.

**Escalation triggers:**
- Change touches onboarding flow — Riley approval required.
- Change touches student-facing copy — Riley review required.
- Change modifies metric definitions or instrumentation — verify against GTM Playbook.
- Change involves database schema — test on Neon branch first.

**Quality gates:**
- If student-facing: Trust, First-Value, UX, Copy, Consistency gates
- If infrastructure: Two-Founder Operational Gate (can it be maintained?)

**What matters most:**
Check prior art before inventing. Prefer extending existing patterns over creating new ones. Student-facing changes carry escalation triggers. Infrastructure changes must pass the two-founder operability test.

### 8. Multi-Domain Orchestration

**Trigger:** A task that spans 2+ domains and benefits from subagent delegation. Examples: redesigning a surface that involves backend + frontend + copy, preparing a fundraising package across brand + product + metrics, launching the freshman wedge across landing + onboarding + GTM.

**Must-read (in order):**
1. [Agent Orchestration Workflow (Current)](/docs/operations/meta/agent-orchestration-workflow-current) — full workflow
2. [Orchestration Checklist (Current)](/docs/operations/meta/orchestration-checklist-current) — one-screen checklist
3. [Subagent Context Packet (Current)](/docs/operations/meta/subagent-context-packet-current) — base context for every subagent
4. This doc (Context Compiler) — to assemble per-subtask context

**How to use the compiler for orchestration:**

1. Identify the subtask domains (e.g., subtask A is `student-copy`, subtask B is `engineering`, subtask C is `fundraising`).
2. Pull the recipe for each subtask's type from this doc.
3. Include the recipe's must-read docs, constraints, and escalation triggers in the subagent brief for that subtask.
4. Apply composition rules (below) for any subtask that spans multiple types.

**Key constraints:**
- Synthesize centrally before delegating. Do not delegate planning.
- Each subagent gets disjoint files and clear scope boundaries.
- Integrate centrally. Review all subagent outputs for coherence and canon compliance.
- Verify the integrated result against Quality Gates before calling work done.

**Escalation triggers:**
- Union of all escalation triggers from all subtask recipes.
- If any subtask touches onboarding or canonical claims, escalation applies to the whole task.

**Quality gates:**
- All gates from all subtask recipes apply to the integrated result.

**What matters most:**
Orchestration quality depends on brief quality. Use the recipes to construct bounded, well-contexted subagent briefs. The lead agent's job is synthesis and integration, not just delegation. Concatenation is not integration.

## Composition Rules

When a task spans multiple types:

1. **Union the must-read lists.** Remove duplicates. If the same doc appears in multiple recipes, keep the most specific "why" annotation.
2. **Union all canonical claims.** All claims from all involved types are in scope.
3. **Strictest escalation wins.** If any recipe triggers escalation, the task escalates.
4. **All quality gates apply.** Union of gates from all recipes.
5. **Combine synthesis.** The "what matters most" for a multi-type task should address the intersection of concerns. Read each recipe's synthesis, then reason about where they constrain each other.

**Example:** A landing page redesign is both `student-copy` and `onboarding` (if it's the entry to the product). Combine both recipes: the landing page must pass the Riley Test (copy recipe) AND preserve time-to-first-value (onboarding recipe) AND escalate to Riley (onboarding hard stop).
