# Agent Orchestration Workflow

Brief workflow for high-tier tasks where a lead agent orchestrates subagents (Claude tasks, other AI agents, or delegated human workers).

## When To Orchestrate vs. Work Solo

**Work solo** when the task is:
- A single-domain change (one file, one service, one doc)
- Quick enough that splitting would add overhead
- Exploratory and the scope isn't clear yet

**Orchestrate** when the task:
- Spans multiple disjoint scopes (e.g., backend + frontend + docs)
- Has independent subtasks that benefit from parallel execution
- Is large enough that a single agent would lose coherence or context

## Workflow

### 1. Read canon first

Before any work, load the relevant source-of-truth docs. See [DormWay Canon Map (Current)](/docs/operations/meta/dormway-canon-map-current) for which docs win. Start from [DormWay Executive Context (Current)](/docs/operations/meta/dormway-executive-context-current) for orientation.

### 2. Bounded discovery

Explore only what's needed to understand the current state. Don't boil the ocean. If the task is in a known domain, go straight to the canonical entry points.

### 3. Synthesize centrally

The lead agent forms the plan, identifies subtasks, and defines scope boundaries. Do not delegate planning — delegate execution of bounded, well-defined subtasks.

### 4. Split by disjoint scopes

Each subagent should own a clearly bounded piece of work with:
- No overlapping files
- No shared mutable state
- Clear inputs and expected outputs

Use the Subagent Brief Template to brief each subagent.

### 5. Give minimal context packets

Each subagent gets only:
- Its objective and scope
- The files it owns
- The constraints and docs it must read
- What it should not change
- Its exact deliverable

Do not dump the full project context into every subagent.

### 6. Integrate centrally

The lead agent:
- Reviews all subagent outputs
- Resolves conflicts or inconsistencies
- Ensures the combined result is coherent

### 7. Verify against quality gates

Run the result through [DormWay Quality Gates (Current)](/docs/operations/meta/dormway-quality-gates-current) before claiming completion. Evidence before assertions.

### 8. Report

Deliver:
- What was done
- What tradeoffs were made
- What risks remain
- What should happen next

## Principles

- **Synthesize first, delegate second.** Don't fan out work before understanding the problem.
- **Bound tightly.** Loose scopes produce drift. Tight scopes produce usable output.
- **Integrate, don't concatenate.** Subagent outputs need a coherent pass, not just assembly.
- **Canon over invention.** Subagents should extend existing patterns, not invent new ones.
- **Two-person test.** The result must be operable by Riley and Ethan.
