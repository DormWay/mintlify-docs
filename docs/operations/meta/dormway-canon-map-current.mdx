# DormWay Canon Map

When docs conflict, this map tells you which one wins.

## Precedence Rules

1. **For engineering/implementation, code wins over docs.** If an engineering doc says "X" but the code does "Y", trust the code. For brand, GTM, strategy, and positioning, the canonical docs are authoritative — there is no "code" to override them.
2. **`status: current` wins over `status: draft`.** Never silently promote a draft into assumed strategy.
3. **Newer current docs win over older current docs** (check `last_updated`).
4. **`status: deprecated` and `status: archived` are reference only.** Do not implement from them.
5. **Generated docs** (`Generated/`) are auto-built summaries. Useful for orientation but not canonical for decisions.

## Doc Status Meaning

| Status | Meaning | Safe to implement from? |
|--------|---------|------------------------|
| `current` | Active, canonical | Yes |
| `draft` | Working idea, not committed | No — verify against current docs or code first |
| `active` | In use but may not be fully verified | Verify key claims first |
| `in-progress` | Actively being worked on | No — treat as draft until promoted |
| `deprecated` | Superseded | No |
| `archived` | Historical | No |
