# DormWay Memory and Chaptering - Research Digest and MVP Spec

## TL;DR
- Core thesis: DormWay can improve retention and reduce "semester blur" by creating explicit learning boundaries ("chapters") and timing lightweight active recall prompts at those boundaries.
- Product wedge: turn each class into a **Save Point** (30-60 seconds) and each day into a short **Recall Loop** (about 2 minutes).
- Delivery rule: interventions must be low-friction and optional to avoid cognitive overload.

## Context
This doc digests a long Gemini research session plus prototype concepts (interactive landing/spec pages). The output quality was mixed: useful strategic direction, but repetitive narrative and inconsistent source quality.

## What Looks Scientifically Directional
- **Retrieval practice over passive review**: learners retain more when they must recall or generate, not only reread.
- **Event boundaries matter**: class end, topic shift, and location transitions are natural moments to "close" one learning segment and encode it.
- **Context cues can help early encoding**: place/context can support recall, but should act as scaffolding, not dependency.
- **Cognitive load constraints are real**: high-energy or frequent prompts can backfire during dense lectures.

## What Needs Caution
- Avoid presenting synthetic charts/numbers as validated outcomes.
- Avoid overclaiming fixed effect sizes (for example, universal "% improvement" language).
- Treat location anchoring as optional support, then transition users to internal retrieval cues.

## DormWay Product Thesis
DormWay should become the layer that:
1. Knows when learning boundaries occur (schedule/time).
2. Captures what should be encoded (course/unit/key terms).
3. Surfaces tiny, timely prompts that convert passive intake into active memory traces.

## MVP (v0) Scope
### 1) Post-Class Save Point (required)
After each class event:
- One-sentence summary ("Today was about...")
- Three key terms
- One "still fuzzy" item

Target completion time: 30-60 seconds.

### 2) Evening Recall Card (required)
Later the same day:
- 1-3 prompts generated from the student's Save Point
- Quick self-rating: `Nailed it` / `Fuzzy`

Target completion time: ~2 minutes.

### 3) Weekly Chapter Recap (required)
End-of-week digest:
- Top concepts captured
- Fuzzy topics count
- Suggested next review targets

### 4) Optional Context Anchor (v0.5)
- Manual location tag (one-tap suggested building/spot)
- Used as a lightweight cue in later recall prompts

## Interaction Rules
- Keep prompts predictable (not random interruptions).
- Trigger at meaningful boundaries (class end, evening window, unit checkpoint).
- Do not require lecture transcription for MVP.
- Do not require persistent GPS/background tracking for MVP.

## Class Modes (v1 Direction)
- **STEM**: variable, formula, step confusion prompts.
- **Humanities**: claim, evidence, counterargument prompts.
- **Language**: vocabulary + sentence generation prompts.
- **Discussion/Seminar**: opposing viewpoints + personal position prompts.

## 2-Week UM Pilot Plan
### Cohort
- 20-50 students

### Success Metrics
- Save Point completion rate per attended class
- Evening Recall completion rate
- Weekly mini-quiz delta (from user-owned keywords/prompts)
- Perceived time distinction score (self-report): "This week felt distinct, not blurry."
- Daily clarity score: "I knew what mattered next."

### Minimum Success Signal
- Sustained weekly usage plus directional lift in recall and perceived week distinctness.

## Risks and Guardrails
- Risk: tool feels like extra homework.
  - Guardrail: strict time caps and defaults to minimal input.
- Risk: gamification distracts from learning objective.
  - Guardrail: game-like interactions are optional skins, not core flow.
- Risk: credibility gap from speculative data visuals.
  - Guardrail: label all concept charts as `Illustrative` unless empirically measured.

### MVP Protocol Hardening (v1)
Primary endpoint:
- 7-day delayed recall score from user-generated Save Point items.

Secondary endpoints:
- Save Point completion rate per attended class.
- Recall Feed completion rate.
- Weekly self-report distinctness score (`0-100`).
- Daily task-initiation latency self-report.

Design minimums:
- Randomization at student-course pair level.
- Baseline capture in week 0 (prior study habits + baseline recall).
- Attrition handling plan defined before launch.
- Feedback loop included in all recall cards to avoid reinforcing wrong memories.

### Interaction Guardrails to Ship
- Notification budget: max 2 nudges/day/course, quiet hours respected, auto-throttle after repeated non-response.
- Save Point hard cap: 60 seconds.
- Manual location tagging default; passive location always opt-in.
- No competitive leaderboard mechanics in MVP.
