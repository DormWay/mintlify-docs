# Home and Widgets

Home V2 is the main widget runtime for LockedIn web. It is batch-first, layout-aware, and built around a fixed canonical widget set rather than arbitrary widget composition.

## Canonical Home Widgets

| Widget type | Canonical ID | Notes |
|-------------|--------------|-------|
| `today` | `widget:today` | singleton |
| `schedule` | `widget:schedule` | aliases exist outside Home V2, not inside it |
| `tasks` | `widget:tasks` | singleton |
| `courses` | `widget:courses` | singleton |
| `headsup` | `widget:headsup` | user-facing label is Cue |

## Important Contracts

- Home V2 renders from `/v2/widgets/batch`
- layout persistence stores geometry, not runtime data
- widget preferences persist separately from layout geometry
- batch responses can partially fail without failing the whole page
- aliases are tolerated in some legacy flows, but Home V2 saves only canonical types

## Cue Layer

Cue is the user-facing name for the Heads Up signal layer. The codebase still uses `headsup` identifiers, but product-facing docs and UI should describe it as Cue unless referring to code names.

## Layout and Realtime

- server layouts are authoritative when they still match the widget set
- legacy local storage can migrate once into server layouts
- realtime invalidation should refresh the widget batch query rather than piecemeal widget fetches
