# Tasks and Assignments

DormWay now treats tasks, assignment completion, and planner blocks as related but distinct layers. The canonical persistent task table is `tasks`, while assignment deadlines and scheduled work still flow through `student_time_blocks`.

## Canonical Storage Layers

| Layer | Canonical use |
|-------|---------------|
| `tasks` | Persistent user task lifecycle: `pending`, `scheduled`, `completed`, `deleted` |
| `assignment_completion` | Completion tracking for Canvas, syllabus, and generic assignments |
| `student_time_blocks` | Assignment deadlines, schedule artifacts, and planner blocks |

## Source Rules

- Canvas sync creates assignment-backed tasks and keeps completion aligned with submissions
- Syllabus tasks can appear as synthetic tasks and use IDs like `syllabus-{courseContextId}-{index}`
- Manual tasks live in `tasks`
- Scheduling a task creates a manual planner block in `student_time_blocks` and links it via `scheduled_block_id`

## Task Bank

Task Bank is the unified unscheduled work surface. It merges:

- persistent tasks
- Canvas assignments
- syllabus-derived tasks
- quick captures
- DayPlan-suggested work

Both `/api/mobile/planner/task-bank` and `/v2/students/me/task-bank` share canonicalization rules so web and mobile do not drift.

## Scheduling Contract

| Action | Result |
|--------|--------|
| Schedule a task | Create `student_time_blocks` row with `source='manual_planner'`, update task to `scheduled` |
| Unschedule a task | Remove planner block, reset task to `pending` |
| Manual planner block | Stored in `student_time_blocks`, soft-deleted via lifecycle status |

## Assignment Completion Rules

- Canvas completion keys use `canvas-<canvas_assignment_id>`
- Syllabus completion keys use `syllabus-<courseContextId>-<index>`
- Manual completion must keep task status and assignment completion in sync
- DueSoon and dashboard surfaces treat submitted or graded Canvas work as completed before overdue logic runs

## Important Invariants

- `tasks` is the canonical lifecycle table
- `student_time_blocks` is still the source for assignment deadlines and scheduled blocks
- DayPlan consumes pending, unscheduled work but does not mutate task rows directly
- Smart Schedule intent writes time blocks; it does not create persistent tasks unless the source came from Task Bank
