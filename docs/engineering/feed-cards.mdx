# Feed Cards

Feed Cards power the Cue layer. They summarize relevant academic, schedule, weather, and campus signals into a small set of ranked cards for web and iOS surfaces.

## Current Contract

- more than 40 card types exist across multiple categories
- cards are scored on a 0 to 100 priority scale
- time relevance windows control whether a card is eligible to show
- the API returns at most 5 cards per request
- dismissals can be permanent or snoozed

## Pipeline

1. read source data from canonical stores like `service_data`
2. build raw card objects
3. apply transforms and scoring
4. filter by time relevance and dismissals
5. return a small ranked set to the client

## Scoring Inputs

- base priority
- severity adjustments
- urgency adjustments
- location or context boosts where appropriate

## Dismissal System

Dismissals are stored and reapplied on subsequent feed requests. The UI should optimistically remove a dismissed card, then invalidate the cached feed so the server-filtered result becomes canonical.
