## Implications for “clean router” goal
- **Routes are the main source of direct DB usage** (72 files, 1,381 hits). Any “no DB in routes” rule will require a large refactor or a targeted allowlist.
- **v2 routes still use direct DB access** (3 files). This is the most visible gap vs. a dormway-core-only policy.
- **Services still use direct DB access** (28 files). If the policy goal is to keep only dormway-core in router code, these services should be migrated to dormway-core factories/services as well.

## Recommended sequencing (inventory-driven)
1. **v2 routes first**: move `v2/students`, `v2/syllabi`, `v2/widgets` to dormway-core services.
2. **Top 10 high-density routes**: `mobile-routes`, `auth0-routes`, `canvas-routes`, `assignment-completion-routes`, `task-routes`, `dashboard-routes`.
3. **Admin routes**: migrate the highest-impact admin pages to dormway-core or central admin services.
4. **Services cleanup**: `dashboard-aurora-service`, `context-data-service`, `setup-status-service`.
