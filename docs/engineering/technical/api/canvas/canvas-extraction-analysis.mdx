# Canvas Extraction Analysis

This document captures how DormWay extracts and normalizes Canvas assignment/submission data for product surfaces.

## Primary Pipeline

- Backend/source integration docs: [Canvas Sync Service Implementation](/docs/engineering/technical/api/canvas/canvas-sync-service-implementation)
- Timeline and implementation narrative: [Canvas Integration Timeline - October 2025](/docs/engineering/technical/api/canvas/canvas-integration-timeline-october-2025)
- Frontend extraction path (web): `services/dormway-lockedin/src/lib/academic/data.ts`

## Extraction Coverage

The Canvas extraction path includes:

- Assignment identity and scheduling fields (`id`, `name`, `due_at`, `course_code`)
- Grading/submission fields (`score`, `grade`, `submitted_at`, submission status)
- Late/missing policy fields (`missing`, `late`, `excused`, `late_policy_status`, `seconds_late`, `points_deducted`)
- Backend-computed status used for UI state (`computed_status`)

## Why This Matters

- Prevents false assignment states in course/timeline views.
- Supports richer status chips and urgency classification.
- Keeps Canvas-derived data semantically aligned with DormWay assignment models.
