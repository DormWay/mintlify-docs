# Ably Real-Time System - Source of Truth

This document is the canonical reference for ALL Ably real-time channels, events, producers, and consumers in the DormWay platform.

## Quick Reference

| Service | Role | Location |
|---------|------|----------|

## Event Catalog

### Invalidation Events

Published to `user:{userId}:updates` with event name `invalidate`:

```typescript
interface InvalidationEvent {
  type: 'invalidate';
  resource: InvalidationResource;
  entityId?: string;
  context?: string;
  ts: number;
}

type InvalidationResource =
  | 'dashboard'
  | 'tasks'
  | 'schedule'
  | 'academic'
  | 'canvas'
  | 'courses'
  | 'profile'
  | 'notifications'
  | 'feed';
```

**Produced by:**
- `api-router/src/services/ably-service.ts`: `publishInvalidation()`, `publishInvalidationBatch()`
- `engine/src/activities/ably.activities.ts`: `publishInvalidation()`, `publishInvalidationBatch()`

**Consumed by:**
- `dormway-lockedin/src/hooks/useRealtimeInvalidation.ts` → invalidates React Query cache

## 🔴 Critical Architecture Gap: Invalidation Coverage

**Linear Ticket:** [DORM-935](https://linear.app/dormwayllc/issue/DORM-935/centralize-ably-invalidation-in-dormway-core)

### Current Problem

Invalidation is fragmented with **~3% coverage** of write operations:

| Category | Write Ops | With Invalidation | Coverage |
|----------|-----------|-------------------|----------|
| Web Routes | 150+ | 8 | 5.3% |
| Admin Routes | 100+ | 0 | 0% |
| Engine Activities | 100+ | 2 | ~2% |

**Critical gaps:**
- Canvas routes: 7 write endpoints, 0 invalidations
- Course lifecycle: 4 write endpoints, 0 invalidations
- Mobile routes: 30+ write endpoints, 0 invalidations

### Current Architecture (Fragmented)

```
api-router/ably-service.ts     → defines InvalidationResource type locally
                               → defines publishInvalidation() locally

engine/ably.activities.ts      → duplicates InvalidationResource type
                               → duplicates publishInvalidation()

dormway-core/ably.adapter.ts   → has generic publish methods
                               → NO invalidation-specific methods
```

### Target Architecture (Centralized)

```
dormway-core/adapters/realtime/
├── ably.adapter.ts           → generic Ably publishing
├── invalidation.ts           → InvalidationResource type
│                             → publishInvalidation()
│                             → publishInvalidationBatch()
│                             → Invalidation registry mapping
└── index.ts                  → exports everything

Domain services call publishInvalidation() after writes
Entity factories can optionally publish invalidation
```

### Implementation Plan

1. **Phase 1:** Move `InvalidationResource` and `publishInvalidation()` to dormway-core
2. **Phase 2:** Create invalidation registry mapping tables to resources
3. **Phase 3:** Instrument domain services to publish after writes

### Toast Suppression Logic

**Canvas noise reduction** (non-admin users):
- `canvas.assignments.updated` with ≤3 changes → suppressed (silent refresh)
- `canvas.grades.updated` → always shown (grades are important)
- `canvas.sync.complete` → shown only if courses or assignments > 0

**Toast Throttling**:
- `notify` library includes built-in throttling via `shouldThrottle()` function
- Prevents toast spam from rapid-fire events

## Red Dot Badge Opportunities

Visual indicators ("red dot badges") help users notice new activity without intrusive toasts. These should appear on navigation items, tabs, or cards.

### High-Value Badge Locations

| Location | Event Trigger | Badge Clears When |
|----------|---------------|-------------------|
| **Courses nav item** | `canvas.grades.updated` | User visits courses page |
| **Courses nav item** | `canvas.assignments.updated` | User visits courses page |
| **Dashboard tab** | `dayplan.update` | User views updated day plan |
| **Documents nav** | `syllabus.completed` | User views the syllabus |
| **Tasks tab/nav** | `canvas.assignments.updated` (new due dates) | User views tasks |
| **Schedule nav** | `canvas.sync.complete` (new events) | User views schedule |

### Implementation Pattern

```typescript
// In a context or hook (e.g., useUnreadBadges)
const [badges, setBadges] = useState<Record<string, boolean>>({
  courses: false,
  tasks: false,
  documents: false,
  schedule: false,
});

// Listen for Ably events
useEffect(() => {
  const handleRealtimeEvent = (event: CustomEvent) => {
    const { name, data } = event.detail;

    if (name === 'canvas.grades.updated' || name === 'canvas.assignments.updated') {
      setBadges(prev => ({ ...prev, courses: true, tasks: true }));
    }
    if (name === 'syllabus.completed') {
      setBadges(prev => ({ ...prev, documents: true }));
    }
    if (name === 'canvas.sync.complete' && data?.assignments > 0) {
      setBadges(prev => ({ ...prev, schedule: true }));
    }
  };

  window.addEventListener('realtime:event', handleRealtimeEvent);
  return () => window.removeEventListener('realtime:event', handleRealtimeEvent);
}, []);

// Clear badge when user visits page
const clearBadge = (key: string) => {
  setBadges(prev => ({ ...prev, [key]: false }));
};
```

### Badge UI Component

```tsx
// In navigation item
<NavItem href="/dashboard/courses">

  {badges.courses && (
    <span className="w-2 h-2 rounded-full bg-red-500 animate-pulse" />

</NavItem>
```

## System Broadcast Capability

The `system:broadcast` channel enables platform-wide announcements to ALL connected users simultaneously.

### Channel Details

| Property | Value |
|----------|-------|
| Channel Name | `system:broadcast` |
| Scope | All authenticated users |
| Current Status | **Exists but underutilized** |
| Producer | engine (via `publishSystemBroadcast()`) |
| Consumers | LockedIn, iOS, Admin (potential) |

### Use Cases

1. **Scheduled Maintenance**: "DormWay will be briefly unavailable for maintenance at 2:00 AM EST"
2. **Feature Announcements**: "🎉 New feature: Course comparison is now available!"
3. **Emergency Alerts**: "We're experiencing issues with Canvas sync. Working on a fix."
4. **Product Updates**: "Version 2.5 is rolling out with improved schedule views"

### Publishing a Broadcast

**From Engine** (Temporal workflow or activity):
```typescript
import { publishSystemBroadcast } from '../services/ably-publisher';

await publishSystemBroadcast({
  type: 'announcement',
  title: 'Scheduled Maintenance',
  message: 'DormWay will be briefly unavailable tonight at 2:00 AM EST.',
  severity: 'info',  // 'info' | 'warning' | 'error'
  dismissible: true,
  expiresAt: '2026-02-04T07:00:00Z',  // Optional: auto-dismiss after this time
});
```

**From dormway-core adapter**:
```typescript
import { getAblyAdapter } from '@dormway/core';

const adapter = getAblyAdapter();
await adapter.publishSystemBroadcast({
  type: 'announcement',
  title: 'New Feature',
  message: 'Course comparison is now available in the Courses tab!',
  severity: 'info',
  dismissible: true,
});
```

### Consuming Broadcasts (Client)

**In RealtimeProvider** (add to existing subscriptions):
```typescript
// Subscribe to system broadcast channel
const broadcastChannel = ably.channels.get('system:broadcast');
broadcastChannel.subscribe('announcement', (message) => {
  const { title, message: body, severity, dismissible } = message.data;

  // Show as banner or modal based on severity
  if (severity === 'error') {
    showBanner({ title, body, variant: 'error', dismissible });
  } else {
    notify[severity](body, { duration: dismissible ? 10000 : Infinity });
  }
});
```

### In-App Announcements (Replaces Email)

**Goal**: Announce features, updates, tips, and news directly in the app instead of email.

**Why in-app beats email:**
- 📬 Emails get buried, filtered, or ignored
- 👀 In-app has ~100% visibility when user is active
- 🎯 Can target by campus, beta status, feature usage
- 📊 Can track views/dismissals/CTA clicks
- ⚡ Instant delivery vs email delays

**Announcement Types:**

| Type | Example | Persistence |
|------|---------|-------------|
| **Feature Launch** | "🎉 Course comparison is here! See how your workload stacks up." | Card until dismissed |
| **Product Update** | "We've improved Canvas sync - grades now update in real-time." | Card for 7 days |
| **Tips & Tricks** | "Pro tip: Use keyboard shortcuts (⌘K) to navigate faster." | Card until dismissed |
| **Onboarding Nudge** | "You haven't connected Canvas yet. Get automatic assignment tracking!" | Card until action taken |
| **Beta Invite** | "Want early access to AI study plans? Join the beta." | Card until dismissed |
| **Seasonal/Event** | "Finals week mode: We've enabled focus features for you." | Card for event duration |
| **Changelog** | "What's new in v2.5: 5 improvements based on your feedback." | Card for 14 days |

**Targeting Options:**

```typescript
await publishAnnouncement({
  type: 'feature-launch',
  title: 'Course Comparison is Here',
  message: 'See how your workload compares across courses.',
  cta: { label: 'Try it now', href: '/dashboard/courses?view=compare' },

  // Targeting (optional - defaults to all users)
  target: {
    audience: 'all',                    // 'all' | 'beta' | 'new-users' | 'power-users'
    campusIds: ['uuid1', 'uuid2'],      // Specific campuses (optional)
    hasFeature: 'canvas-connected',      // Users with specific feature enabled
    excludeFeature: 'dismissed-compare', // Exclude users who dismissed before
  },

  // Lifecycle
  startsAt: '2026-02-03T09:00:00Z',     // Don't show before this time
  expiresAt: '2026-02-17T00:00:00Z',    // Auto-remove after 2 weeks
  dismissible: true,
  priority: 'normal',                    // 'low' | 'normal' | 'high'
});
```

### Priority Card in Feed (Opportunity)

Instead of fleeting toasts, high-priority broadcasts could render as a **pinned card** at the top of the dashboard feed. This provides:
- **Persistence** - Card stays until user dismisses or it expires
- **Rich content** - Can include links, CTAs, images
- **Better visibility** - Doesn't disappear after 5 seconds

**Suggested Event Structure:**
```typescript
await publishSystemBroadcast({
  type: 'priority-card',
  title: 'Canvas Integration Now Available',
  message: 'Connect your Canvas account to automatically sync assignments and grades.',
  severity: 'info',
  cta: {
    label: 'Connect Canvas',
    href: '/dashboard/integrations?setup=canvas',
  },
  icon: 'graduation-cap',  // Lucide icon name
  dismissible: true,
  expiresAt: '2026-02-10T00:00:00Z',
});
```

**Feed Integration Pattern:**
```typescript
// In dashboard feed/widget data hook
const [priorityCards, setPriorityCards] = useState<PriorityCard[]>([]);
const [dismissedCards, setDismissedCards] = useLocalStorage<string[]>('dismissed-cards', []);

useEffect(() => {
  const channel = ably.channels.get('system:broadcast');
  channel.subscribe('priority-card', (message) => {
    const card = message.data;
    // Don't show if already dismissed or expired
    if (dismissedCards.includes(card.id)) return;
    if (card.expiresAt && new Date(card.expiresAt) < new Date()) return;

    setPriorityCards(prev => [card, ...prev.filter(c => c.id !== card.id)]);
  });
}, []);

// Render at top of feed
{priorityCards.map(card => (
  <PriorityCardWidget
    key={card.id}
    {...card}
    onDismiss={() => {
      setDismissedCards(prev => [...prev, card.id]);
      setPriorityCards(prev => prev.filter(c => c.id !== card.id));
    }}
  />
))}
```

**Priority Card vs Toast Decision Matrix:**

| Scenario | Use Toast | Use Priority Card |
|----------|-----------|-------------------|
| Brief status update | ✅ | |
| Maintenance in 1 hour | ✅ | |
| New feature announcement | | ✅ |
| Action required from user | | ✅ |
| Ongoing incident | | ✅ |
| Processing complete | ✅ | |
| Beta invite/onboarding CTA | | ✅ |

### Broadcast Best Practices

1. **Use sparingly** - Broadcasts interrupt all users; reserve for important announcements
2. **Keep messages short** - Users should understand in <5 seconds
3. **Set expiration** - Auto-dismiss stale announcements
4. **Make dismissible** - Unless truly critical (downtime, data loss)
5. **Test in dev first** - Use `dev-telemetry` channel for testing
6. **Choose the right format** - Toast for transient, card for persistent/actionable

## Debugging Checklist

1. **Message not arriving?**
   - Check channel name matches exactly (case-sensitive)
   - Verify producer is actually publishing (check logs)
   - Confirm consumer is subscribed to correct channel
   - Check Ably connection state

2. **UI not updating?**
   - For LockedIn: Check if receiving `invalidate` event (not just informational events)
   - Open realtime debug view in LockedIn
   - Verify React Query key mapping

3. **Telemetry not processing?**
   - Confirm using correct telemetry channel (`prod-telemetry` vs `dev-telemetry`)
   - Check ably-relay is running and subscribed
