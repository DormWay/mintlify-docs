# Next.js Middleware Guide

Guide for DormWay LockedIn middleware behavior and routing constraints.

## Source of Truth

- Middleware implementation: `.repos/dormway-platform/services/dormway-lockedin/src/middleware.ts`

## Protected Route Model

- Protected route families include `/dashboard/*` and `/onboarding/*`.
- API routes are explicitly excluded from middleware auth enforcement (`/api/*`).
- Well-known routes (`/.well-known/*`) are excluded.

## Onboarding Redirect Rules

- If user is not onboarded and requests a non-onboarding protected route, middleware redirects to `/onboarding`.
- If user is onboarded and requests `/onboarding`, middleware redirects to `/dashboard/today`.
- Query params are preserved across redirects.
- A short-lived `onboardingJustCompleted` cookie bypass exists to avoid redirect races immediately after completion.

## Operational Notes

- There are explicit bypasses for development debug routes and local E2E auth bypass mode.
- Demo static/embed mode has dedicated guard logic and should be reviewed before changing auth flow behavior.
