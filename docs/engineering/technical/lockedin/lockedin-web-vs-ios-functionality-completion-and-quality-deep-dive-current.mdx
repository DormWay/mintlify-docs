## Current Functional Parity Snapshot

| Surface | Current Status | Summary |
|---|---|---|
| Navigation IA | Aligned | `Today, Schedule, Tasks, Courses, Library` now matches across web and iOS/iPad. |
| Today | Diverged (intentional) | Web uses grid/layout-editor model; iOS uses curated stack model. Outcome parity still required. |
| Tasks | Partial | Web has deeper planner and bulk semantics; iOS has ghost planner UI but no persisted planner scheduling/bulk parity yet. |
| Schedule | Partial | Web stronger on ingest/config controls; iOS stronger on alarms/live activity/work-session execution. |
| Courses/Term | Partial | Both strong, but composition and capability emphasis differ by platform. |
| Library | Partial | Web has richer mode model; iOS has strong native files/notes workflows, especially on iPad. |
| Settings | Partial | Web has broad centralized taxonomy; iOS is split across settings sheet/Me/legacy settings surfaces. |

## Completion Assessment (What Is Actually Done vs Missing)

### Meaningfully complete now
1. Cross-platform IA alignment at primary nav/tab level.
2. Brandbook implementation exists as live, token-driven reference (`/dev/brandbook`).
3. iOS has mature native shell split (iPhone tabs + iPad split view + Catalyst-aware paths).

### Not complete yet (highest parity impact)
1. Tasks planner outcome parity on iOS:
   - Current iOS task service does not expose schedule/unschedule parity methods.
   - Current iOS Tasks flow ends ghost drag without persisting schedule mutation.
2. Tasks bulk semantic parity on iOS:
   - No current bulk mode equivalent to web bulk complete/delete semantics.
3. Settings taxonomy parity:
   - Needs canonical mapping between web's broad settings model and iOS entry points.
4. Today capability contract lock:
   - Need canonical list of required outcomes independent of layout model.
5. Library model mapping lock:
   - Need explicit web mode/object lifecycle to native section mapping.

## Quality Assessment

### Web quality posture
1. Strong tokenization and implementation discipline in brandbook and global surface primitives.
2. Active schedule refactor/testing artifacts and explicit QA runbook documents.
3. Existing unfinished placeholders still present in some product areas, but parity docs are specific and execution-oriented.

### iOS quality posture
1. Strong package modularization and broad package-level test footprint.
2. Strong design system infrastructure and mature liquid glass/material layer.
3. App-layer parity-critical gaps remain in Tasks and some app-level reliability items from the iOS quality audit.

### Notable quality risk signals to track
1. iOS app-layer parity gap in Tasks planner/bulk semantics (product behavior mismatch risk).
2. iOS app-layer audit findings still open (data refresh, error handling, forced cast, app-level testing depth).
3. Placeholder and unfinished implementation debt remains active:
   - iOS app views still include explicit unfinished/placeholder markers.
   - Web dashboard/components also include explicit unfinished/placeholder markers.

## Brandbook and Styling Implications for iOS

DormWay brandbook is now implementation-grade, not just copy/design guidance.

iOS should align to brandbook on:
1. Token semantics (brand, semantic states, surface hierarchy).
2. Motion and accessibility gates (reduced motion/transparency, contrast discipline).
3. Voice posture in UI copy (direct, calm, actionable).

iOS should not mirror web-specific mechanics:
1. Web layout editor and nav rail mechanics.
2. Desktop density patterns that reduce touch ergonomics.

Reference: [LockedIn Brandbook Dev Page - Design & Styling Reference (Current)](/docs/engineering/technical/lockedin/lockedin-brandbook-dev-page-design-styling-reference-current)

## Required iOS Consideration Plan (Program Order)
1. Execute Tasks slice #1 first (planner persistence + bulk semantics parity).
2. Execute Settings slice #1 second (taxonomy + side-effect parity mapping).
3. Lock Today capability contract before Today slice implementation.
4. Lock Library model mapping before Library slice implementation.
5. Run iPhone + iPad + Mac Catalyst quality gates for each slice before broad rollout.

## Coding Guardrails for Future Agents
1. Treat web behavior as source of truth for product semantics.
2. Treat native shell/interaction ergonomics as source of truth for iOS UX form.
3. Do not ship parity slices without documenting intentional divergences.
4. Keep brandbook and parity docs in sync whenever foundation tokens, semantics, or slice order changes.
