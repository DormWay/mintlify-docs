# Ambassador Platform Integration

DormWay integrates with [Ambassador](https://getambassador.com) for referral tracking and attribution. This document covers the current implementation.

## Architecture

### Referral Attribution Flow

```mermaid
sequenceDiagram
    participant User
    participant App as Web/iOS
    participant API as API Router
    participant Temporal
    participant Activity as Ambassador Activity
    participant Ambassador as Ambassador API

    User->>App: Click referral link (e.g., join.dormway.app/7fjnwc)
    App->>App: Capture referral code
    User->>App: Complete onboarding
    App->>API: POST /onboarding/complete {referralCode}
    API->>Temporal: Start onboardStudent workflow
    Temporal->>Activity: processReferralAttribution()
    Activity->>Ambassador: POST /referral_attribution/record/
    Ambassador-->>Activity: Attribution confirmed
    Activity->>Activity: Update accounts table
    Activity->>Activity: Insert referral_events
    Activity-->>Temporal: {success: true}
```

### Key Design Decisions

1. **Temporal Workflow**: Referral attribution runs as a Temporal activity inside `onboardStudent`, making it:
   - **Repeatable** - Temporal retries on transient failures
   - **Consistent** - All platforms use the same workflow
   - **Retriggerable** - Admin can retrigger with referral code

2. **Non-blocking Validation**: If Ambassador API validation fails, we still attempt to record the attribution. Ambassador validates the `short_code` during recording.

3. **Idempotent Operations**: All database updates use `COALESCE` to avoid overwriting existing data. Ambassador returns 409 for duplicate attributions (safe to ignore).

### Database Schema

**accounts table columns:**
- `referred_by` (UUID, FK) - User ID of referrer
- `referral_code_used` (TEXT) - The short code used
- `referred_at` (TIMESTAMPTZ) - When attribution occurred
- `ambassador_external_id` (TEXT) - Ambassador platform ID
- `ambassador_status` (TEXT) - 'active', 'pending', etc.

**referral_events table:**
- `referrer_id` - Ambassador user ID
- `referred_id` - New user ID
- `event_type` - 'onboarding_complete'
- `status` - 'synced' or 'pending'

### Activity: processReferralAttribution

```typescript
// services/engine/src/activities/ambassador.activities.ts
export async function processReferralAttribution(params: {
  userId: string;
  userEmail: string;
  firstName?: string;
  lastName?: string;
  referralCode: string;
  campusName?: string;
}): Promise<{ success: boolean; referrerId?: string; attributionUid?: number; error?: string }>
```

**Steps:**
1. Validate referral code via `/ambassador/all/` (non-blocking)
2. Find referrer in local database
3. Record attribution via `/referral_attribution/record/`
4. Update `accounts` table
5. Insert into `referral_events`

## Ambassador API Reference

### Authentication

Ambassador uses path-based authentication:
```
https://api.getambassador.com/api/v2/{username}/{token}/json/{endpoint}/
```

### Endpoints Used

#### GET /ambassador/all/
Lookup ambassador by short code:
```typescript
params: { short_code: "7fjnwc" }
// Response: { ambassadors: [...] } or { response: { data: { ambassadors: [...] } } }
```

#### POST /referral_attribution/record/
Record referral attribution (parameters as query string):
```typescript
params: {
  short_code: "7fjnwc",      // Identifies the advocate
  customer_email: "user@example.com",
  customer_uid: "uuid",       // Our user ID
  customer_status: "enrolled",
  campaign_uid: "12345",
  first_name: "John",
  last_name: "Doe"
}
// Response: { response: { data: { referral_attribution: { uid, advocate, customer } } } }
```

## Platform-Specific Details

### Web (dormway-lockedin)

Referral codes are captured from URL parameters on landing pages and stored in session. On onboarding completion:

```typescript
// mobile-routes.ts validates with Zod
referralCode: z.string().max(64).regex(/^[A-Za-z0-9_-]*$/).optional()
```

### iOS

`ReferralService.swift` handles:
1. Capturing referral code from universal links (`join.dormway.app/{code}`)
2. Storing in UserDefaults
3. Passing to onboarding API

### Admin Retrigger

Admin UI at `/users` allows retriggering onboarding with optional referral code:
- Queries existing `referral_code_used` from database
- Allows override via text input
- Passes to `onboardStudent` workflow
