# DayPlan V2

DayPlan is DormWay's daily intelligence artifact. V2 is the current production path and is centered on a priority-first daily brief instead of a minute-by-minute scheduler.

## Core Facts

| Property | Current contract |
|----------|------------------|
| generation time | 5 AM user local time |
| storage | `service_data` with method `dayplan` |
| trigger owner | StudentWatcher |
| downstream effects | feed generation, briefings, client refreshes |

## V2 Output Shape

The important V2 fields are:

- `dueToday`
- `hardCommitments`
- `conflicts`
- `suggestedBlocks`
- `nearFuture`
- `summary`
- `notificationContent`
- `currentState`

Older timeline fields still exist for compatibility, but V2's product meaning comes from the priority-first fields above.

## Generation Flow

1. StudentWatcher decides a new day plan is needed
2. generation activities pull current data and prior-state context
3. the plan prompt is built with anti-hallucination rules
4. the model returns the structured plan
5. the plan is stored and can trigger feed regeneration and outbound delivery work

## Important Contracts

- generation is timezone-aware
- `currentState` updates separately from full plan generation
- downstream systems should not treat every state touch as a full plan refresh
- Ace can reference DayPlan as context, but Ace does not own schedule recommendations
