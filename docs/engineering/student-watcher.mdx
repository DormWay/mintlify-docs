# StudentWatcher Workflow

StudentWatcher is DormWay's per-student Temporal digital twin. There is one long-running workflow per student, and it owns the background rhythm for daily planning, notification triggers, sync evaluation, and context-driven updates.

## Overview

| Property | Value |
|----------|-------|
| Workflow name | `studentWatcherWorkflow` |
| Task queue | `student-worker` |
| Workflow ID pattern | `student-watcher-${studentId}` |
| Source file | `services/engine/src/workflows/studentWatcher.simplified.workflow.ts` |

The workflow starts during onboarding or signup flows and rolls forward with `continueAsNew` to keep Temporal history manageable.

## Key Signals

- `daily_plan`
- `context_update`
- `generate_plan`
- `preferences_update`
- `trigger_calendar_sync`
- `trigger_canvas_sync`
- `send_evening_briefing`
- `generate_feed_cards`
- `test_push_notification`
- `send_push_notification`
- `trigger_dayplan_push`

## Runtime Cadence

- main loop checks roughly every 5 minutes
- DayPlan generation happens at 5 AM in the user's timezone
- evening briefing uses the configured evening hour
- calendar and Canvas sync are evaluated hourly and usually trigger when last successful sync is 6 hours old or older
- auto-sync driven plan regeneration is throttled so it does not churn constantly

## Start Points

- signup and onboarding flows can start it
- admin routes can signal it
- city-level sync jobs can fan out signals to relevant student workflows

## City Fan-Out

City-driven updates can signal both home-campus students and traveling students whose GPS location is near a campus in the target city. That traveling-student logic is part of the current production contract, not a future idea.

## Persisted State

- `student_watcher_state` stores the workflow's durable state snapshots
- workflow status queries expose current plan and generation metadata

## Known Risk

`preferences-routes` still uses `studentWatcher-${userId}` in one path while the canonical workflow ID is `student-watcher-${userId}`. Signals sent with the old format can miss the active workflow.
