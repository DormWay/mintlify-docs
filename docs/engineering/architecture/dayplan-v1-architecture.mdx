# DayPlan V1 Architecture

This document captures the legacy DayPlan architecture that predated the priority-first v2 system.

## Scope

- Historical reference for legacy behavior and migration context.
- Not the current implementation path for new work.

## Legacy Characteristics

- DayPlan generation relied on a less explicit prioritization model than v2.
- Data shaping and reconciliation had tighter coupling between assignment and schedule inputs.
- Rendering assumptions were more brittle across clients than the current widget-first model.

## Known Pain Points

- Assignment retrieval/regression risk was higher in the v1 era.
- The v2 architecture doc records a concrete regression where assignment joins introduced missing assignment behavior.
