# SoT - Crews & Find Us Time (Proposed)

## Scope
- Private, invite-only group coordination in DormWay (`Crew`).
- `Find Us Time` scheduling loop: availability capture, ranked recommendations, session confirmation.
- Contract boundaries across `dormway-core`, `api-router`, iOS, and web.

## Non-Goals
- Public social graph behavior (feeds, followers, leaderboards, discoverability by strangers).
- Replacing existing scheduling primitives (`student_time_blocks`, term/conflict/deadline pipelines).
- Org billing/monetization or advanced marketplace behavior in V1.

## Terminology Contract
- `Crew`: social/private group object used by students to coordinate.
- `Find Us Time`: scheduling module inside a `Crew`.
- AI orchestration must not use `crew` in user-facing naming; use `Agent Workflow` / `Agent Run`.

## Invariants and Contracts
- Busy windows are source-of-truth; free time is inferred and must be user-confirmed before lock-in.
- DormWay users can prefill from schedule/deadline/conflict signals; guests use manual availability first.
- Privacy default is aggregate overlap only; no raw personal event details shared cross-member by default.
- Recommendation ranking is server-owned (`dormway-core`) and deterministic in V1.
- Two-person comparison is first-class and uses the same recommendation/confirmation contract.
- Link-first flow is launch-valid; contact sync is a phase-2 acceleration layer, not a launch blocker.

## Key Flows
1. `Create Crew` -> generate invite artifacts -> open `Find Us Time`.
2. Invitees join via link (guest or signed-in) -> submit availability quickly.
3. Server ranks top candidate slots with reason chips.
4. Organizer/admin confirms slot -> create `crew_session` -> emit activity + reminders.
