# Tech Stack

DormWay is a multi-repo, multi-runtime product. This page captures the technologies currently in use across the main student surfaces and the backend systems that keep them current.

<Note>
  Version callouts on this page were rechecked against the live repo manifests on **April 3, 2026**. For deployment topology, treat this as the logical stack first and the vendor map second.
</Note>

---

## Web App (`dormway-lockedin`)

| Technology | Role |
|-----------|------|
| **Next.js 15.5.7** | App Router web client for the core student product |
| **React 19.2.1** | UI runtime |
| **TypeScript 5.x** | Main application language |
| **Tailwind CSS 3.4** | Styling system |
| **TanStack Query 5.90** | Client-side server-state management |
| **Clerk** | Auth on the web surface |
| **Ably** | Realtime client delivery |
| **Sanity** | Content-backed surfaces where needed |
| **Motion / Framer Motion** | Rich interaction and animation layers |
| **Vercel Analytics / Speed Insights** | Web instrumentation on the client side |

The web app also carries the current Today customization system, public school pages, and student growth/program surfaces.

---

## Native Apple App (`ios-clean`)

| Technology | Role |
|-----------|------|
| **Swift 6** | Main application language |
| **SwiftUI** | UI framework |
| **iOS 18+** | Current deployment target |
| **WidgetKit** | Home screen widget support |
| **ActivityKit / AlarmKit** | Live Activities and class alarms on supported devices |
| **App Intents** | Siri and shortcut-style system integrations |
| **PencilKit** | Rich note and lecture workflows on iPad-class surfaces |
| **Ably** | Realtime delivery into the dashboard store |

The iOS app is modularized through Swift packages and uses a dashboard composite endpoint rather than direct Aurora-style reads.

## API and Workflow Layer

### Gateway and BFF

| Technology | Role |
|-----------|------|
| **Zuplo 6** | Public API gateway layer |
| **Node.js + Express 5.1.0** | `api-router` BFF for web and iOS |
| **TypeScript** | Main backend language |
| **@dormway/core** | Shared domain/entity library used across services |

### Durable workflows

| Technology | Role |
|-----------|------|
| **Temporal 1.11.x** | Durable workflow orchestration |
| **Node.js 20.x** | Workflow runtime in `engine` |
| **date-fns / date-fns-tz** | Timezone-aware scheduling logic |

### AI batch and document pipelines

| Technology | Role |
|-----------|------|
| **Python service layer** | AI-heavy background work such as syllabus analysis |
| **Ragie** | Document indexing and retrieval-backed Q&A |
| **OpenAI SDK** | LLM access in the workflow layer |
| **Portkey** | LLM gateway and observability |
| **node-ical / PDF parsers / OCR utilities** | File and calendar ingestion support |

---

## Data, Identity, and Realtime

| Technology | Role |
|-----------|------|
| **PostgreSQL** | Primary relational store |
| **Neon** | Managed Postgres with branch-based developer workflow |
| **PostGIS** | Geospatial campus/location support |
| **Clerk** | Primary user auth and session identity |
| **Auth0 / Supabase integrations** | Still present in parts of the backend and adjacent workflows |
| **Ably** | Realtime pub/sub transport |
| **Redis** | Caching and coordination where needed |

Important operational rule: application-safe queries use `DATABASE_URL`, while admin and workflow paths may use `DATABASE_URL_ADMIN`.

---

## Observability and Operations

| Technology | Role |
|-----------|------|
| **OpenTelemetry** | Distributed tracing across backend services |
| **Sentry** | Error monitoring on the web and backend |
| **Doppler** | Secrets and environment management |
| **Docker** | Local and service container workflows |

The exact deployment host mix can change by environment. DormWay's architecture docs should stay anchored to service boundaries and data contracts first.

## Notes on Accuracy

- `@dormway/core` is the target center of gravity for shared backend logic, but some legacy direct database usage still remains in parts of `api-router`
- Hosting details evolve faster than package/framework choices, so this page intentionally emphasizes stable stack decisions over one specific vendor diagram
