# Product Capabilities

DormWay is broad, but the product makes the most sense when grouped by student jobs instead of by a raw feature dump. The core theme across every capability is the same: merge what school already knows, keep it current, and show the student the right amount of information at the right moment.

---

## 1. Public Entry and Activation Surfaces

DormWay now has real product surface area before the main authenticated workspace.

### Live or active public/PLG surfaces

- **Grade calculator** as the clearest no-auth value surface
- **Campus and course SEO pages** that expose real school and syllabus intelligence
- **Pre-semester signup** for incoming students before their fall schedule or Canvas account exists
- **Campus Discovery** as the source-quality gate behind student-visible campus pages
- **Guest/shareable patterns** that show value before the student commits to full setup

### Current capability rule

The public layer should not be a fake demo. It should be a real piece of utility that naturally leads into the maintained student product.

## 2. Awareness and Daily Triage

The highest-value capability in DormWay is fast awareness. The product should help a student answer "am I okay?" before it asks them to do anything more ambitious.

Key product rules for this layer:

- Priority beats pure chronology
- The screen should never create false confidence
- The default should work with no customization
- Anything that looks certain should be source-backed

## 3. Schedule and Task Consolidation

DormWay's second major job is to turn fragmented academic obligations into one coherent timeline and one coherent task list.

### Schedule capabilities

- **Schedule import** from PDFs, screenshots, and calendar sources
- **Class and event normalization** into time-aware blocks
- **Explicit future-term setup** that uses the selected term's campus calendar dates instead of the currently active term's dates
- **Admin support uploads** that map directly into schedule import without generic file reclassification
- **Manual time blocks** for study, meetings, office hours, or personal events
- **Recurring schedule support** where the source data provides it
- **Cross-source merge and deduplication** so the same event does not keep appearing as separate realities

### Task capabilities

- **Multi-source task list** combining Canvas, syllabus extraction, and manual inputs
- **Urgency grouping** so overdue and due-soon work rises above the backlog
- **Planning actions** that turn work into scheduled time instead of leaving it abstract
- **Capacity and workload framing** so a student can see when the week is genuinely overloaded

This is one of DormWay's most important structural differences from a generic planner: the product is not waiting for the student to type every assignment into existence.

## 4. Syllabus and Course Intelligence

Uploading a syllabus is one of DormWay's strongest activation moments because it unlocks information students usually only have buried inside a PDF.

Current capabilities in this layer include:

- **Deadline extraction** for exams, assignments, quizzes, and recurring course events
- **Policy extraction** for grading, attendance, late work, office hours, and course rules
- **Date normalization** across term boundaries and recurring patterns
- **Course intelligence** such as realistic weekly hours, hidden workload, red flags, and opportunities
- **Term-level insight** like peak weeks, workload clusters, and collision detection across courses
- **Conflict computation** that distinguishes between low-stakes pileups and genuinely dangerous clusters

The product goal is not just "read the syllabus." It is "turn syllabus information into something operationally useful all semester."

---

## 5. Sync, Realtime, and Smart Delivery

DormWay is designed so the student does not have to babysit freshness.

Key capabilities:

- **Canvas connection** for courses, assignments, announcements, and grade changes
- **Calendar and schedule syncs** evaluated on recurring cadences
- **Read-replica routing for eligible read-heavy API paths** so public, mobile, and dashboard reads can avoid unnecessary primary load
- **Queue-bound schedule processing direction** so background reconciliation does not starve onboarding or explicit imports
- **Ably-powered realtime delivery** for important changes to student state
- **Smart notification timing** that treats student attention as finite instead of blasting everything immediately
- **Context-aware updates** when a class changes, a deadline moves, or the student's schedule meaningfully shifts

This layer is easy to miss because it mostly shows up as "DormWay stayed right without me touching it." That is exactly the point.

---

## 6. Ace and Document Intelligence

Ace is the conversational layer on top of the student's own academic context. The product should make it feel like the student is talking to their semester, not to a generic chatbot.

Current capabilities include:

- **Course-aware chat** using the student's courses, deadlines, and documents
- **Document question-answering** grounded in uploaded materials and syllabus context
- **Task-aware actions** where read operations are instant and mutations require confirmation
- **A tighter trust boundary** than generic AI tools, because the assistant is meant to help with dates, context, and decisions, not fabricate certainty

The broader rule is the same as the rest of DormWay: the assistant should reduce uncertainty, not create new trust problems.

---

## 7. Library, Notes, and Study Materials

DormWay is not only about due dates. It also needs to give students a useful home for the materials surrounding their coursework.

This includes:

- **Library surfaces** for recent lectures, notes, recordings, and course materials
- **Document-aware workflows** that let Ace and other tools answer against those materials
- **Richer note and lecture experiences on larger Apple surfaces**, including PencilKit-based workflows where available

The long-term product value here is continuity: a student's deadlines, schedule, notes, and materials should feel like parts of the same system.

---

## 8. Collaboration Through Crews

Crews gives DormWay a multiplayer layer for study groups, project teams, dorm groups, and other shared contexts.

Core capabilities include:

- **Group chat and shared coordination**
- **Find Times** for availability collection and ranked meeting suggestions
- **Deadline-aware group spaces** when the crew is tied to academic work
- **Shared files plus document Q&A** for the group's own materials
- **Shared tasks, notes, polls, and coordination workflows**

The important distinction is that Crews is not just chat. It is group coordination anchored to the same academic context graph the rest of DormWay uses.

---

## 9. Personalization and Platform-Specific Features

DormWay supports adaptation without making customization a prerequisite for value.

### Web

- Persistent layout on Today
- Drag-and-drop reordering
- Widget resizing
- Hide and restore behavior
- Add-widget flows
- Shape-adaptive widgets that reinterpret themselves based on available space

### iPhone and iPad

- Native SwiftUI client
- Home screen widgets via WidgetKit
- Live Activities and alarm-based time-awareness on supported devices
- Deeper note-taking and study workflows on iPad-class surfaces

The product principle is straightforward: **great defaults first, customization available second**.
