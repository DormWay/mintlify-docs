# For Investors

DormWay looks like a simple student product on the surface: today view, schedule, tasks, notes, and an assistant. Underneath it is a system built to maintain a live academic state for each student and use that state across multiple surfaces in realtime.

This page explains the technical moat, not the marketing story.

---

## Why This Category Is Hard

The core student problem is not "students need another to-do list." It is that school happens across multiple systems that do not merge:

- Canvas knows some deadlines
- Syllabi hold the rest
- Calendars know time, not academic priority
- Group tools do not understand course context
- Generic AI tools do not know the student's actual semester state

DormWay's technical advantage comes from solving the merge problem and the freshness problem at the same time.

---

## 1. Per-Student Durable Compute

Every active student can be backed by a long-running Temporal workflow called **StudentWatcher**. That means DormWay does not treat the student as a static row plus a cron schedule. It treats the student as a durable computational unit that can:

- Receive signals when state changes
- Regenerate plans and schedule views when needed
- Maintain execution state over long periods
- Survive deploys, restarts, and transient failures
- Keep the product fresh without asking the student to do maintenance work

This is one of the hardest pieces to replicate because it is a systems architecture choice, not a feature toggle.

---

## 2. Cross-Source Merge With Trust Constraints

DormWay does not win by storing tasks. It wins by merging conflicting academic realities into one trusted state:

- Canvas assignments
- Syllabus-derived dates and policies
- Imported schedules and calendars
- Manual student edits
- Campus and term context

The defensibility is not just in extraction. It is in the merge logic, normalization, deduplication, and conflict computation that make the system trustworthy enough to power the primary student view.

That trust layer matters. DormWay is intentionally conservative about what gets presented as certain. If the main screen says a student is clear, it has to mean it.

---

## 3. Syllabus Intelligence as Structured Infrastructure

Syllabus upload is not treated as document storage. It is treated as a structured ingestion event that can produce:

- Deadlines and exam dates
- Recurring academic events
- Policy extraction
- Grading and weighting signals
- Course-specific workload and risk indicators
- Cross-course conflict and peak-week computation

This creates a durable course graph and term graph that generic AI wrappers do not have. Once the course is structured, the output can feed Today, notifications, conflict detection, Ace, and future planning layers.

---

## 4. Context Graph and Campus Layer

DormWay maintains a graph of cities, campuses, buildings, courses, terms, and students instead of modeling everything as disconnected application records.

That enables:

- Campus-aware timing and relevance
- Building and travel-time reasoning
- Term-aware logic instead of generic calendar logic
- More credible personalization for notifications, day plans, and schedule intelligence
- School-specific public surfaces and onboarding paths at scale

DormWay's current registry covers **6,134+ campuses**, which is both a product asset and a growth asset.

---

## 5. Realtime Delivery Across Multiple Surfaces

DormWay is not just a web dashboard. The same underlying student state has to stay coherent across:

- Web
- Native iPhone and iPad
- Realtime updates
- Widget and alert surfaces
- Group coordination in Crews
- School-specific public landing surfaces

That matters strategically because the same merge engine and student context model get amortized across more than one client. The result is deeper product depth without building isolated one-off systems for each surface.

---

## 6. Why This Compounds

The moat is not any one feature. It is the way the layers reinforce each other:

- Better source coverage creates better student state
- Better student state creates better Today, notifications, and Ace responses
- Better campus and course structure improves onboarding and public school surfaces
- Durable workflows reduce maintenance load on the student and the system
- Native surfaces increase switching cost and raise the replication bar

---

## Competitive Read

Most competitors are strong at one slice:

- LMSes know assignments but not the student's actual week
- Calendars know time but not academic risk
- AI study tools know prompts but not the student's verified semester state
- Group chat tools know people but not course context

DormWay's differentiation is that it merges those layers into one maintained student state and reuses that state everywhere.

### Current market context

The April 2026 competitive work sharpens the comparison:

- **Coursicle** is the closest direct competitor because it already has LMS sync and real student distribution, but it still lacks DormWay's AI syllabus intelligence and deeper multi-surface state model.
- **Notion** is the biggest ambient threat because it is free for students and widely adopted, but it is still a blank-canvas workspace, not a student-specific system that updates itself.
- **MyStudyLife** remains a polished planner, but it does not operate at the same US college data depth or social/coordination layer.

---

## Summary

DormWay's defensibility comes from building the hard middle layer between school data and student action:

- durable per-student workflows
- cross-source merge and trust logic
- syllabus-to-structure intelligence
- campus and course context graphs
- realtime delivery across web and native clients

That combination is much harder to copy than any one headline feature.
