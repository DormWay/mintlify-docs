## Root Causes

1. No canonical action descriptor shared across UI surfaces.
2. No central action execution API with typed intents and consistent response semantics.
3. Legacy/static quick-links path still present in dashboard composite transformer.
4. Inspector and Command/Search contracts are partially implemented but not normalized around one action layer.
5. Dead/unused components remain in tree, splitting maintenance energy.

---

## Target Architecture (End-to-End)

### 1) Canonical quick-action model
- Introduce a shared `QuickActionDescriptor` (id, label, icon, category, eligibility, context bindings, telemetry metadata, execution target).
- Use this descriptor in:
  - Command Palette
  - Today Inspector
  - Widget-level action rows
  - Ace quick actions menu
  - Course/assignment detail surfaces

### 2) Centralized execution contract
- Add `POST /api/v2/actions/execute` in api-router.
- Request shape:
  - `actionId`
  - `entityRef` (kind/id/source ids)
  - `context` (surface, term/course ids, timestamp)
- Response shape:
  - `status` (`success|partial|failed`)
  - `uiHints` (toast message, next entity focus, deep link)
  - `telemetryPayload`

### 3) Widget batch action metadata
- Extend relevant `/v2/widgets/batch` envelopes to return contextual `actions[]`.
- Keep widget render data separate from action execution payload.
- Preserve provenance/freshness metadata for action confidence.

### 4) Inspector-first interaction consistency
- For entity-bearing quick actions, prefer opening inspector/focus context first.
- Keep "Open full view" as explicit secondary step.
- Resolve URL-state standardization decision (`?inspector=` current vs `?focus=` target).

### 5) Telemetry and health
- Required event family:
  - `quick_action_shown`
  - `quick_action_clicked`
  - `quick_action_succeeded`
  - `quick_action_failed`
- Include: `surface`, `entity_kind`, `action_id`, `source`, `latency_ms`, `error_class`.

## Phased Implementation Plan

### Phase 0 - Contract Alignment (1 to 2 days)
**Goal**: Lock architecture and avoid parallel implementations.

Tasks:
- Decide canonical URL state strategy for focus/inspector.
- Define `QuickActionDescriptor` and execution payload contracts.
- Decide deprecation fate of `ActionPopover` and `AssignmentDrawer`.

DoD:
- ADR-style decision note in this plan or linked architecture note.
- Shared action schema committed in web + api-router type layers.

---

### Phase 1 - Quick Wins and Dead-End Removal (2 to 4 days)
**Goal**: Remove obvious regressions and no-op actions.

Tasks:
- Wire `AcademicPulse` quick actions in `SyllabusTermView`.
- Replace `onSelectCourse` no-op in `SyllabusTermView` with real navigation/inspector open.
- Wire `CourseDrawer` quick-action buttons to actual handlers.
- Remove or explicitly deprecate unused quick-action surfaces (`ActionPopover`, `AssignmentDrawer`) from active path.

DoD:
- No visible dead/no-op quick actions in audited surfaces.
- Regression test pass for dashboard term and course details.

---

### Phase 2 - Unified Frontend Action Registry (3 to 5 days)
**Goal**: One source of truth for action definitions in web.

Tasks:
- Build `quick-actions/registry` + `quick-actions/resolver` modules.
- Migrate Command Palette action items to registry-driven generation.
- Migrate Ace quick-actions menu to registry-driven actions.
- Migrate inspector action buttons to shared execution wrappers.

DoD:
- At least 3 major surfaces consume shared descriptors.
- Surface-specific overrides only in resolver logic, not ad-hoc component arrays.

---

### Phase 3 - Backend Execute API + Batch Action Metadata (4 to 7 days)
**Goal**: Move from local static actions to server-coordinated action system.

Tasks:
- Implement `POST /api/v2/actions/execute` in api-router.
- Add action resolution services for core actions (complete task, mark assignment complete, open canvas deep links, create time block, etc.).
- Add contextual action metadata in `/v2/widgets/batch` payloads for Today/Courses/Tasks where applicable.
- Start deprecating static quick-links generation path in composite transformer for primary flows.

DoD:
- Command palette and inspector can execute at least one shared backend action path each.
- Action failures return typed, user-safe errors.

---

### Phase 4 - Context-Aware Ranking and Cross-Platform Parity Hooks (3 to 5 days)
**Goal**: Improve relevance and parity readiness.

Tasks:
- Add ranking/scoring service for context-aware action ordering.
- Ensure core web action IDs map cleanly for iOS parity follow-up.
- Add parity test checklist against mobile plan expectations.

DoD:
- Action ordering changes based on context with deterministic fallback.
- Documented action ID map for web <-> mobile parity.

## Testing Strategy

### Functional
- Cmd+K actions execute correctly and do not collide with Ace.
- Inspector actions complete state transitions and reflect updates without stale UI.
- Course and assignment actions preserve deep-link safety constraints.

### Contract
- Type-level tests for action descriptors and execute payloads.
- API tests for `/api/v2/actions/execute` success/failure cases.
- Widget batch contract tests for action metadata presence/shape.

### Regression
- Ensure no dead buttons in audited quick-action surfaces.
- Validate no reintroduction of duplicate Cmd+K ownership.
