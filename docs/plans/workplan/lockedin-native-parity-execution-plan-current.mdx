# LockedIn Native Parity Execution Plan (Current)

## Definition of Done
Parity is complete when all are true:
1. Functional parity: core web user jobs have equivalent native outcomes.
2. Behavioral parity: defaults, edge cases, and side effects match target semantics.
3. Platform quality parity: iPhone, iPadOS split-view, and Mac Catalyst quality pass.
4. Engineering quality parity: reliability, tests, and performance meet release gates.

## Prioritization Model
Use score:
`priority_score = (impact + reach + pain + strategic_value) - (effort + rework_risk + dependency_risk)`

Current recommended order:
1. Tasks slice #1.
2. Settings slice #1.
3. Today slice #1 (after canonical contract lock).
4. Library slice #1.
5. Schedule slice #1.
6. Courses slice #1.

## Dependency Map
### D0 (must lock early)
1. Canonical Today capability contract.
2. Canonical Settings taxonomy and mapping.
3. Canonical Library mode/object mapping.

### D1 (shared contracts)
1. Navigation/deep-link/intent mapping.
2. Shortcut mapping parity across iPhone/iPad/Catalyst.

### D2 (shared semantics)
1. Tasks semantic contract.
2. Settings semantic contract.
3. Library semantic contract.

### D3 (surface slices)
1. Implement and ship slices behind flags where risk is medium/high.

### Phase C: Surface Delivery

### Phase D: Platform Quality Hardening

### Phase E: Reliability + Performance + Release Readiness
Deliverables:
1. Targeted test coverage for parity-critical flows.
2. Error-path and crash-path verification.
3. Performance validation on touched tabs.

7. Run platform QA on each shipped slice.

## Release Gates
### Functional
1. Equivalent outcomes on touched flows.
2. Matching defaults/filter/edge-case semantics.

### Platform
1. iPhone usability gate.
2. iPad split-view and keyboard/pointer gate.
3. Mac Catalyst keyboard/resize/pointer gate.

### Reliability
1. Loading/error/empty states verified.
2. No new high-severity crashes on touched paths.

### Performance
1. No meaningful interaction or load regressions on touched tabs.

### Documentation
1. Intentional divergences documented.
2. Each slice records files changed, tests run, QA outcomes, and remaining risks.
