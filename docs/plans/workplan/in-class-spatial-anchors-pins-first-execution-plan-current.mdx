# In-Class Spatial Anchors Pins-First Execution Plan (Current)

## Goal
Ship the in-class widget as a pins-first capture flow:
1. `Space` = keep, `Shift` = question.
2. Capture writes canonical lecture pin first.
3. Notebook remains async projection, never canonical.
4. Failures remain recoverable via pending sync + retry.

## Scope
Primary scope is web app implementation in:
- `.repos/dormway-platform/services/dormway-lockedin`

Backend support for pin metadata is already present in:
- `.repos/dormway-platform/services/shared/dormway-core`
- `.repos/dormway-platform/services/api-router`

## Current Baseline (Code-Verified)
1. In-class widget stores local highlight packets and syncs to notes.
   - `.repos/dormway-platform/services/dormway-lockedin/src/app/dashboard/today/widgets/InClassWidget.tsx`
   - `.repos/dormway-platform/services/dormway-lockedin/src/lib/inClassCapture.ts`
2. Game capture emits `kind + caption` only (no spatial payload yet).
   - `.repos/dormway-platform/services/dormway-lockedin/src/lib/in-class-game-engine.ts`
3. Lecture pin metadata is accepted and persisted in backend/core.
   - `.repos/dormway-platform/services/shared/dormway-core/src/entities/lecture/lecture.types.ts`
   - `.repos/dormway-platform/services/shared/dormway-core/src/entities/lecture/lecture.factory.ts`
   - `.repos/dormway-platform/services/api-router/src/routes/v2/lectures.routes.ts`
4. `useCreatePin` hook exists but is not yet used by `InClassWidget`.
   - `.repos/dormway-platform/services/dormway-lockedin/src/hooks/useLectures.ts`

   - `captureKind` (`keep | question`)

   - `clientAnchorId`
2. Add feature flag:
   - `NEXT_PUBLIC_FEATURE_IN_CLASS_SPATIAL_ANCHORS_V1`
3. Ensure code path can toggle between legacy notes-first and pins-first.

### Phase 3: Resolve Active Lecture + Canonical Pin Write
Objective: write to lecture pin endpoint when context is available.

   - build capture draft with metadata + `clientAnchorId`

3. Pin mapping:
   - keep -> `highlight`
   - question -> `question`
4. Compute `audioTimestamp` best-effort from class event timing.

Acceptance:
1. Active class captures create lecture pins.
2. No active lecture falls back without data loss.

Modify:
- `.repos/dormway-platform/services/dormway-lockedin/src/lib/inClassCapture.ts`

- `.repos/dormway-platform/services/dormway-lockedin/src/lib/offline/offline-queue.ts`

Work:
1. Extend packet model with:
   - `syncState` (`pending_sync | synced | failed`)
   - `pinId?`
   - `lastError?`
2. Queue failed writes as offline actions (idempotent via `clientAnchorId`).
3. Retry on:
   - browser online event
   - tab visibility regain
   - optional manual retry UI action
4. Render status in widget recent list and summary chips.

Acceptance:
1. Network/API failure shows pending state, not silent drop.
2. Recovery transitions packet to `synced`.

### Phase 5: Notebook as Async Projection
Objective: keep notebook support without canonical dual-write.

Modify:
- `.repos/dormway-platform/services/dormway-lockedin/src/lib/inClassCapture.ts`

Work:
1. Trigger notebook projection only after:
   - pin write success, or

2. Add idempotency guard in notebook projection using `clientAnchorId`.
3. Keep projection failures non-blocking.

Acceptance:
1. No duplicate notebook entries across retries.
2. Canonical capture success unaffected by notebook sync failures.
