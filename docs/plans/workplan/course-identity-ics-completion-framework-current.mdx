# Course Identity + ICS Completion Framework (Current)

> Canonical plan for current Courses issues (cross-listed dedupe, overdue accuracy, timeline clarity) and the forward architecture that scales across U.S. campuses.

## Context

This plan captures current production pain points reported in the Courses redesign cycle, especially for ICS-connected users (no Canvas PAT available at some schools, including University of Michigan student accounts).

The most visible example has been `MKT 407/COMM 317`, where cross-listed identity drift caused split rendering across Courses, Tasks, and Schedule surfaces.

## Current Issues

1. **Cross-listed course identity drift**
   - Same real course can appear as separate entities (`MKT 407`, `COMM 317`, combined variants).
   - Side effects: duplicate columns/cards, wrong color assignment, inconsistent schedule grouping.

2. **False overdue signals for ICS users**
   - ICS feeds often expose due dates but not reliable completion/submission state.
   - Current UI can still show overdue for completed work when completion telemetry is unavailable.

3. **Timeline usability and clarity gaps**
   - Dot chart density is hard to parse quickly.
   - Height/position semantics are not self-evident.
   - The model can appear to emphasize past items and overwhelm users.

4. **Interaction model is not actionable enough**
   - Users need direct click targets by item/date/type to open details and take action.
   - At-a-glance status and "what to do next" are not consistently linked.

## What Exists Now (Already Implemented)

1. Alias-aware normalization improvements for cross-listed course codes.
2. Stronger canonical course resolution in schedule and tasks grouping paths.
3. Guardrails to reduce aggressive overdue labeling when source telemetry is limited.
4. Course/task/schedule coherence improvements for known cross-listed fixtures.

- `.repos/dormway-platform/docs/plans/2026-02-20-course-identity-and-completion-framework.md`

## Current Architecture Assessment

The current direction is **functional and materially better**, but it is **not yet the final long-term framework** for all institutions.

What is good:
1. Canonicalization is happening earlier in normalization paths.
2. UI-level split rendering regressions are reduced.
3. ICS capability limits are now acknowledged in status behavior.

What still needs hardening:
1. Deterministic identity precedence must be formalized and enforced end-to-end.
2. Completion semantics must become source-capability-aware by contract.
3. Timeline UI must prioritize comprehension and action over compressed plotting.

## Long-Term Framework (Cross-University Safe)

### 1) Deterministic Course Identity (Required)

Identity precedence must be tenant-scoped and source-aware:
1. `tenant_id + source + course_context_id` (strongest)
2. `tenant_id + source + native_course_id`
3. `tenant_id + term_id + normalized_course_code + section + meeting_signature`

Rule: never dedupe globally by raw display text or normalized course code alone.

### 2) Assignment Identity Graph (Required)

Persist equivalence links instead of ad-hoc matching:
1. `assignment_identity` records per source object.
2. `assignment_identity_links` with confidence + rationale.
3. Reads prefer strong identity links before heuristic fallback.

### 3) Capability-Aware Status Semantics (Required)

Separate:
1. `due_state` (date relation)
2. `completion_state` (`complete` / `incomplete` / `unknown`)
3. `confidence` (high/medium/low)

For ICS-only integrations:
1. default completion to `unknown` unless explicit completion exists.
2. avoid hard overdue assertions when completion is `unknown`.
3. use language like "needs review" when certainty is low.

### 4) Scoped Heuristic Matching (Required)

Any heuristic matching must be scoped by:
1. tenant
2. term
3. canonical course identity

Then match by title/date/time only as fallback, with confidence tracking.

### 5) Observability and Drift Detection (Required)

Track:
1. split-course render rate
2. false-overdue correction rate
3. unmatched assignment rate
4. fallback matcher usage rate
5. cross-listed alias collision rate

## Timeline / Calendar UX Redesign Direction

Replace tiny dense dot-only visualization with an actionable model:
1. **Primary surface**: agenda-first list grouped as `Now`, `Next 2 weeks`, `Later`.
2. **Secondary surface**: optional compressed timeline for pattern scanning only.
3. **Explicit click targets** on each item (open detail, mark state, jump to course).
4. **Legend and semantics** always visible (what color/position means).
5. **Default filters** prioritize upcoming and unresolved items over past completed work.

## Execution Plan

### Phase 1: Contract + Semantics Hardening
1. Finalize identity precedence contract in API + engine payloads.
2. Introduce capability flags (`supportsCompletionState`, `supportsSubmissionState`).
3. Remove hard overdue assertions for `completion_state=unknown`.

### Phase 2: Identity Graph + Backfill
1. Add identity/link tables and background linker job.
2. Backfill active + recent terms.
3. Add duplicate course reconciliation report by tenant/term.

### Phase 3: Courses/Tasks/Schedule UI Coherence
1. Use canonical identity for color, grouping, and labels across all three surfaces.
2. Add "primary label + alias chip" for cross-listed courses.
3. Ensure schedule and tasks never split the same canonical course.

### Phase 4: Timeline UX Rebuild
1. Make agenda-first view the default.
2. Keep compact timeline as optional layer with clear semantics.
3. Instrument click-through and completion-correction metrics.

## Acceptance Criteria

- [ ] No duplicate rendering for a canonical course across Courses/Tasks/Schedule within same tenant+term.
- [ ] ICS users do not see hard overdue for items with unknown completion state.
- [ ] Timeline semantics are obvious without training (usability review sign-off).
- [ ] Every timeline item has direct detail/action click targets.
- [ ] Observability dashboards track identity drift and overdue confidence.
