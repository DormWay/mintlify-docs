# LockedIn Native Parity Tasks Slice #1 (Current)

## Slice Goal
Close highest-ROI Tasks parity gap by shipping:
1. Planner scheduling outcome parity (native task drop persists schedule state).
2. Bulk semantic parity (multi-select complete/delete behavior with manual-only delete semantics).

## Verified Baseline
### Web baseline
1. Bulk mode and bulk actions are implemented.
2. Planner scheduling presets and task scheduling flows are implemented.
3. Task scheduling contract exists in v2 API.

### Native baseline
1. Ghost planner UI exists but schedule persistence needs explicit wiring.
2. Tasks service currently lacks schedule/unschedule semantics.
3. Native lacks full web-equivalent bulk mode semantics.

## In Scope
1. Persist task schedule outcome on drag/drop commit.
2. Bulk mode:
   - multi-select,
   - bulk complete,
   - bulk delete with explicit skip behavior for non-manual tasks.
3. iPhone, iPadOS, and Mac Catalyst QA for these outcomes.

## Out of Scope
1. Full web filter/search/view parity.
2. Full command/shortcut parity for all task actions.
3. Broader planner preset UX parity beyond core scheduling semantics.

## Acceptance Criteria
### Planner
1. Valid drop creates persisted schedule outcome.
2. UI refresh reflects scheduled semantics.
3. Invalid/conflicting drop does not mutate task state.
4. Scheduled result is visible from Schedule after refresh.

### Bulk
1. Enter/exit bulk mode safely.
2. Select/unselect/clear works predictably.
3. Bulk complete reports success/failure counts.
4. Bulk delete deletes manual tasks and reports skipped items.
5. Selection resets and list refreshes after successful action.

### Platform Quality
1. iPhone: bulk actions reachable within two interaction layers.
2. iPadOS: split-view remains stable in bulk mode.
3. Mac Catalyst: pointer/keyboard flows remain functional.

### Reliability
1. Network failures do not corrupt selection/task state.
2. No crashes from rapid repeated bulk/drag actions.
